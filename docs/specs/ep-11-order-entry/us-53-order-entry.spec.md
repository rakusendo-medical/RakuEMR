## ユーザーストーリー

- **As a** 主治医
- **I want** 患者に対して新規オーダを 1 つのダイアログから種別を選んで起票したい
- **So that** 処方・注射・検査・リハ等のオーダを、種別ごとに画面を覚え直すことなく素早く登録できる

## 画面要素（要素ツリー）

汎用フォーム（種別に依存しない共通項目のみ）。種別ごとの専用項目は本ストーリーのスコープ外。

```
- 「オーダー入力」ボタン: カルテ画面のアクションバー（KarteActionBar）に既存／クリックでダイアログを開く
- 新規オーダ作成ダイアログ (Dialog): open 時のみ表示
  - タイトル: 「新規オーダ作成」
  - 対象患者表示: 患者番号・氏名を固定表示（入力不可・データソース=対象 Patient）
  - オーダ種別 (Select・必須): OrderType 全 10 種（処方／注射／検査／画像／心理検査／ECT／リハビリ／入院定時／IF／テキスト）。ラベルは指示簿タブの ORDER_TYPE_LABEL に準拠（文字→「テキスト」表示）
      - ※種別＝処方／入院定時 のときは、以下「内容／スケジュール」に代えて**処方専用フォーム**を表示（[us-54](./us-54-order-entry-prescription.spec.md)）
  - 内容 (TextField 複数行・必須): オーダ内容の自由記述（例: 検査名・実施内容）。※処方種別では非表示（処方専用フォームで代替）
  - 開始日 (DatePicker/date・必須): 既定＝本日
  - 日数 (NumberField): 既定＝1。0 のとき「継続」（終了日なし）扱い
  - スケジュール (TextField・任意): 実施タイミングの記述（例: 朝食後、1 日 3 回、隔日 など）。※処方種別では非表示（用法／頓服で代替）
  - 担当医表示: ログイン医師名を固定表示（入力不可・データソース＝ログイン医師）
  - バリデーション警告 (Text): 必須未入力・日数不正のとき該当メッセージ（送信不可時のガイド）
  - フッター:
    - キャンセルボタン: 変更を破棄して閉じる
    - 登録ボタン: 必須が揃うまで非活性。クリックでオーダ登録
```

> 表示ラベルは指示簿タブ（`OrdersTab`）の `ORDER_TYPE_LABEL` と一致させる（種別表記の二重管理を避ける）。

## 振る舞い

- **ダイアログを開く**: カルテ アクションバーの「オーダー入力」ボタン → 新規オーダ作成ダイアログが開く。フォームは初期値（種別=未選択、内容=空、開始日=本日、日数=1、担当医=ログイン医師）で表示。
- **種別を選ぶ**: オーダ種別セレクトで 10 種から 1 つ選択。
- **必須を満たす**: 種別・内容・開始日がすべて入力されると登録ボタンが活性化。いずれか欠けている間は非活性。
- **日数の扱い**: 日数 0 を入力すると「継続」（指示簿タブの期間表示で「〜（継続）」）になる。負数は不可（バリデーションエラー）。
- **登録する**: 登録ボタン → 新規 Order（status=「指示済」）を作成し、動的オーダ一覧へ追加。ダイアログを閉じ、スナックバー「オーダを登録しました」を表示。
- **一覧へ反映**: 追加したオーダが、対象患者のカルテ指示簿タブ（`us-50`）一覧・オーダ管理画面・患者メイン「最新オーダ」に即時表示される（seed の静的 ORDERS と合成）。
- **キャンセルする**: キャンセル/背景クリック → 入力を破棄して閉じる（一覧は変化しない）。
- **リロード**: モックのためセッション限定。リロードで登録分は消え、seed（静的 ORDERS）のみに戻る。

## 受け入れ基準（AC）

- [ ] **AC-1: ダイアログ起動**
  - **Given** カルテ画面（`/karte/:patientId`）を開いている
  - **When** アクションバーの「オーダー入力」ボタンを押す
  - **Then** 「新規オーダ作成」ダイアログが開き、対象患者の患者番号・氏名が表示される
- [ ] **AC-2: 種別 10 種の選択**
  - **Given** ダイアログが開いている
  - **When** オーダ種別セレクトを開く
  - **Then** 処方／注射／検査／画像／心理検査／ECT／リハビリ／入院定時／IF／テキスト の 10 種が選べる（テキストは内部値「文字」に対応）
- [ ] **AC-3: 必須バリデーションで登録可否が変わる**
  - **Given** ダイアログが開いている
  - **When** 種別・内容・開始日のいずれかが未入力
  - **Then** 登録ボタンは非活性。3 つが揃うと活性化する
- [ ] **AC-4: 登録が指示簿一覧に反映される**
  - **Given** 種別・内容・開始日を入力済み
  - **When** 登録ボタンを押す
  - **Then** ダイアログが閉じ「オーダを登録しました」が表示され、カルテ指示簿タブ（閲覧一覧）に status=「指示済」で当該オーダが現れる
- [ ] **AC-5: 日数 0 は「継続」**
  - **Given** 日数に 0 を入力して登録した
  - **When** 指示簿タブでそのオーダの期間表示を見る
  - **Then** 「（開始日）〜（継続）」と表示される
- [ ] **AC-6: キャンセルで破棄**
  - **Given** フォームに入力した状態
  - **When** キャンセルを押す
  - **Then** ダイアログが閉じ、一覧にオーダは追加されない
- [ ] **AC-7: セッション限定（非永続）**
  - **Given** オーダを登録した
  - **When** ページをリロードする
  - **Then** 登録したオーダは消え、seed の静的オーダのみが表示される

## 状態遷移 / バリデーション

| 項目 | 必須 | ルール |
| --- | --- | --- |
| オーダ種別 | ○ | OrderType 10 種のいずれか |
| 内容 | ○ | 空文字不可（trim 後 1 文字以上） |
| 開始日 | ○ | 日付。既定＝本日 |
| 日数 | - | 整数 ≥ 0。0＝継続。負数は不可 |
| スケジュール | - | 自由記述 |
| 担当医 | - | 入力不可（ログイン医師名を固定表示・登録時にそのまま `doctorName` へ） |

登録される Order の初期値: `status='指示済'`（確定）、`id` は新規採番、`patientId`/`patientName` は対象患者、`doctorName`＝ログイン医師、`timeSlots` は未設定。

## 補足

- **実装方針**: 病床移動（us-02）と同じ「seed 静的データ＋動的追加分の合成」パターンを踏襲。store に `dynamicOrders: Order[]` と `addOrder(o)` を追加し、`OrdersTab`／`OrderManagement` は `ORDERS` と合成した一覧を参照する。非永続化（partialize から除外）。
- **起点（合意メモ）**: 指示簿タブ（`OrdersTab`／us-50）は「指示済みオーダの閲覧一覧」であり新規入力の場所ではない（PM 指摘）。新規オーダ作成は**カルテ アクションバーの「オーダー入力」ボタン**（`KarteActionBar` の `order-input`）を起点とし、登録結果は指示簿タブ一覧に反映される。当初案の患者メイン（`PatientMain.tsx`）ボタンは同画面が未ルーティング＝到達不能のため不採用（ボタン自体の配線は将来復活時用に残置）。
- **テスト**: 本プロジェクトの test-first 方針に従い、実装前に Playwright E2E（AC-1〜AC-4 を最小カバー）を用意する。
- **後続**: 種別ごとの専用項目、編集・中止・複製、指示簿タブからの起票導線、DO オーダ／オーダセットは ep-11 の後続ストーリーで扱う。
- **PM 確定事項（2026-07-22）**: ①参考システムマニュアル p.865-1600＝第5章 オーダリング（実 PDF で確認済み）、②新規オーダの初期 status＝「指示済」で確定、③担当医＝ログイン医師固定（入力不可）。
