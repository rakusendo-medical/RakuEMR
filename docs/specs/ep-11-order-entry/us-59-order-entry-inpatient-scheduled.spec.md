> マニュアル確認の結果、入院定時オーダは**独立画面ではなく「入院専用の定時処方」＝処方オーダの一種**だった。入力は処方（Rp・薬剤・用量・用法・日数）と同じで、差分は退院連動・処変・中止・ロック等の**運用側の挙動**。本ラウンドは入力（指示まで）を対象とし、処方ダイアログを流用する。

## ユーザーストーリー

- **As a** 主治医
- **I want** 入院患者に対して、入院専用の定時処方（Rp・日数指定）を作成・指示したい
- **So that** 入院中の定時薬を処方オーダと同じ操作で登録できる

## スコープ

### 含む（モック）

- オーダ送信画面「入院定時」ボタン → **処方ダイアログ（[us-54](./us-54-order-entry-prescription.spec.md) 流用）** を種別 `入院定時` で開く
  - Rp テーブル＋処方追加（かな検索／処方セット／過去のオーダー）／一包化・後発／開始日・日数・終了日 は処方と同じ
- 登録 → 作成中オーダ → [指示] → 指示簿へ `入院定時` で反映

### 含まない（モック簡略・後続）

- 退院確定時の自動削除、処方変更（処変）と日数管理（当初日数への復帰）、指定日以降の中止・中止取消
- オーダ変更ロック、会計・調剤連携の変更情報送信設定
- ※これら運用側挙動は「オーダ実施」系エピックの対象。本ストーリーは指示（入力）まで。

## 画面要素（要素ツリー）

処方ダイアログ（[us-54](./us-54-order-entry-prescription.spec.md)）と同一。見出しのみ種別に応じて「入院定時オーダ」となる。

```
- 処方ダイアログ (Dialog): 見出し「入院定時オーダ　対象患者: {患者番号}　{氏名}」（共通 `OrderDialogTitle`・濃紺バー）
  - オーダ内容（Rp テーブル）／新しい Rp として薬剤を追加／一包化・後発（全）
  - 開始日・日数・終了日（双方向連動）
  - フッター: 閉じる（破棄確認）／登録
```

## 振る舞い

- **入院定時を開く**: オーダ送信画面「入院定時」→ 処方ダイアログ（種別＝入院定時）。
- **薬剤を追加・登録**: 処方（[us-54](./us-54-order-entry-prescription.spec.md)）と同じ（Rp 採番・処方追加・処方セット・過去のオーダー・一包化/後発・日数）。
- **指示 → 反映**: [指示] で store へ追加 → 指示簿タブに `入院定時` で反映。

## 受け入れ基準（AC）

- [ ] **AC-1: 入院定時ボタンで処方ダイアログが開く**
  - **Given** オーダ送信画面を開いている
  - **When** 「入院定時」ボタンを押す
  - **Then** 処方ダイアログ（種別＝入院定時・見出し「入院定時オーダ」）が開く
- [ ] **AC-2: 薬剤を追加→登録→指示で指示簿に反映**
  - **Given** 入院定時ダイアログで薬剤を Rp に追加した
  - **When** 登録 → [指示]
  - **Then** 指示簿タブに `入院定時` で当該オーダが現れる

## 補足

- 入力ダイアログは処方（[us-54](./us-54-order-entry-prescription.spec.md)）と共用（`PrescriptionDialog` を種別 `入院定時` で起動）。マスタも処方の医薬品マスタ／処方セットを使用。
- 入院専用の注記（`note`）は、当初はダイアログ上部に表示する想定だったが、PM 判断により**表示しない**方針に変更済み（実装でも注記は出さない）。退院確定時の自動削除・処変・中止・ロック等の運用側挙動は「オーダ実施」系エピックの対象。
- 現行 seed の `入院定時` オーダはバイタル測定・血糖測定（非薬剤の定時タスク）で登録されているが、これはマニュアルの「入院定時＝定時処方」とは意味が異なる既存データ。PM 判断により**マニュアル準拠（定時処方）**で実装し、seed は既存のまま残す（過去のオーダー復元では名称のみ復元される）。
