# 仕様（specs）

ユーザーストーリー単位の **実装仕様（spec）** を保管する場所。

## 目的

`docs/issues/` のエピック・ストーリーを「GitHub Issue 投入用ドラフト」として保ったまま、本ディレクトリではモック実装を駆動する **詳細仕様** を持つ。

- spec を SoT（Single Source of Truth）として、現状モックとの差分を `docs/changes/<epic>.md` に切り出す
- 実装時は spec の受け入れ基準（AC）をチェックリストとして使う

## ディレクトリ構成

```
docs/specs/
├── README.md                          # 本ファイル
├── _template.spec.md                  # ストーリー spec テンプレ
└── ep-XX-<slug>/
    ├── _epic.md                       # エピックレベル spec
    ├── us-XX-<slug>.spec.md           # ストーリー spec
    └── ...
```

## 命名規則

| 種別 | パス |
| --- | --- |
| エピック spec | `ep-XX-<slug>/_epic.md` |
| ストーリー spec | `ep-XX-<slug>/us-XX-<slug>.spec.md` |

`<slug>` は `docs/issues/` の既存ファイル名と揃える。

## ストーリー spec のセクション

1. **メタ** — 対応エピック、対応モック画面、参考システムマニュアル参照ページ
2. **画面要素** — 画面に存在すべき要素と役割（マークアップ的な構造ではなく、責務記述）
3. **振る舞い** — 操作と期待される結果（イベントベース）
4. **受け入れ基準** — Given/When/Then（実装の合否判定に使う）
5. **状態遷移 / バリデーション** — 必要に応じて

エピック spec のセクションは `_template.spec.md` の末尾を参照。

## 参考システムマニュアルの引用ルール

- ページ範囲は `docs/manuals/参考システムマニュアル対応表.xlsx` から該当行を引用する
- ファイル名は対応表通り（`01 基本システム.pdf` / `02 看護支援オプション.pdf`）
- 製品名・ベンダー名は記載しない（[CLAUDE.md](../../CLAUDE.md) 固有名詞ポリシー参照）

## 改修フロー（spec 駆動）

エピック単位でラウンドを切る。

1. 当該エピックの全ストーリーについて spec を起こす
2. `docs/screen-mapping.tsv` を更新（画面パス ↔ ストーリー）
3. 現状モックを spec の AC で照合し、未充足項目を `docs/changes/ep-XX-<slug>.md` に列挙
4. 改修着手 → spec の AC を 1 件ずつ満たしていく
5. 全 AC グリーンでそのエピックをクローズ、次エピックへ
