## 振る舞い

- **入院予定患者氏名クリック (赤文字)** / **日付未定者一覧の患者番号クリック**: 入院手続きダイアログを開く。指示時の入力が初期値
- **入院日 or 食事開始日変更**: 入院日時から食事開始日時までの間に「食無し」指示（マスタ設定により「臨時欠食」）が自動生成される。マスタ設定は本モックでは固定挙動でよい
- **病室未定の場合**: 入院手続き時に病室・ベッドを実値で確定する（病棟は指示時に確定済。**手続き完了＝病室確定**が前提のため、病室未定のままでは手続き不可。モックでは病室確定済の入院予定者からのみ手続きを起動）
- **空床照会ボタン**: カレンダー形式の空床状況ダイアログを開く（us-07 と同じダイアログを共有可）
- **入院確定実行**:
  1. 入院日が未来日時 → エラー（確定不可）
  2. 未実施の外来専用オーダがある → オーダ確認ダイアログ
  3. 食事開始日時が変更されている AND 操作者が医師でない AND オーダ中止操作を行う → 代行入力認証ダイアログ
  4. 確定: 患者氏名表示が赤→黒、カルテ画面・医師指示簿に確定内容書込
- **更新ボタン**: 入力内容を保存し未確定のままダイアログを閉じる（カレンダーは赤文字のまま）
- **指示箋印刷チェック**: 確定／更新と同時に食事箋・移動箋を印刷扱い（モックでは UI のみ）

## 受け入れ基準（AC）

- [ ] **AC-1: 入院予定患者から手続き画面を開ける**
  - **Given** 入退院情報画面または病棟マップを表示している
  - **When** 入院予定患者の氏名（赤文字）をクリックする、または日付未定者一覧から患者番号をクリックする
  - **Then** 入院手続きダイアログが開かれ、入院指示時の入力（入院日・食事開始日・病室・紹介医療機関・入院決定理由・指示内容など）が初期表示される（入院時文書は取り扱わない）

- [ ] **AC-2: 入院日・食事開始日を変更できる**
  - **Given** 入院手続きダイアログを開いている
  - **When** 入院日または食事開始日（時間帯含む）を入院期間内に変更する
  - **Then** 入院日時から食事開始日時までの間に「食無し」指示（マスタ設定により「臨時欠食」）が自動生成される

- [ ] **AC-3: 病室未定の患者の病室情報を確定できる**
  - **Given** 病室・ベッドが未定（病室未定）である、または指示時から変更が必要（病棟は確定済）
  - **When** 病室・ベッドを実値で設定する
  - **Then** 当該病室・ベッドで確定される（病室未定のままでは入院手続きを完了できない）

- [ ] **AC-4: 空床照会から空床状況を確認できる**
  - **Given** 入院手続きダイアログを開いている
  - **When** 「空床照会」を実行する
  - **Then** 空床照会ダイアログがカレンダー形式で病棟の空床状況を表示する

- [ ] **AC-5: 入院確定すると未実施オーダの確認が出る**
  - **Given** 患者に未実施の外来専用オーダが残っている
  - **When** 入院確定を実行する
  - **Then** 入院確定時のオーダ確認ダイアログが表示され、選択チェックでオーダを中止できる

- [ ] **AC-6: 入院確定後の状態が反映される**
  - **Given** 入院確定が完了した
  - **When** 各画面を確認する
  - **Then** 患者氏名表示が赤→黒に変わり、カルテ画面・医師指示簿に確定内容が書き込まれる

- [ ] **AC-7: 未来日付では入院確定できない**
  - **Given** 入院日に未来日付が設定されている
  - **When** 入院確定を実行しようとする
  - **Then** 確定できない（指示の更新は可能）

- [ ] **AC-8: 医師以外が食事開始日を変更すると代行依頼指示となる**
  - **Given** 医師以外の職員が入院確定を行う
  - **When** 食事開始日時を変更している
  - **Then** 当該食事療法は入院指示医による代行依頼指示として登録される（オーダ中止操作を伴う場合は代行入力認証ダイアログが表示され、認証医を選択する）

- [ ] **AC-9: 指示箋印刷チェックで食事箋・移動箋を出力できる**
  - **Given** 指示箋を印刷するチェックを付けて確定／更新する
  - **When** 操作ボタンをクリックする
  - **Then** 食事箋・移動箋が印刷される（チェック有無の初期値・名称はマスタで設定）

## 状態遷移 / バリデーション

- ダイアログ状態: 開く → 入力 → 確定/更新 → 閉じる（ESCでキャンセル）
- 確定可否判定:
  - 入院日 ≤ 現在 → 確定可
  - 入院日 > 現在 → 確定不可、更新は可
- 食事開始日 ≥ 入院日 を保証（バリデーション）
- 食事開始日 - 入院日 > 0 の場合、自動で「食無し」指示生成（モックでは生成イベント記録のみで可）
- 操作者ロール: モックでは `currentUserRole: 'doctor' | 'staff'` を仮想的に切替可能にし、staff の場合に代行依頼ロジックを通す

## 補足

- **入院時文書は現時点では電子カルテで取り扱わないため、本仕様から除外（2026-08-17）**。以前は入院時文書チェック一覧（作成状況・作成医付き）を表示していたが、UI・データとも削除済み。
- 再入院の場合、食事内容は前回入院時の内容が初期値となる（モックでは未対応 / 現状値固定）
- 外部精神科システム連携オプション利用時は「精神科入院有無」項目が追加表示される（モックでは表示分岐のみ）
- 病棟マップの患者操作メニューからも入院手続きダイアログを開けるようにする（us-01 操作メニューを将来拡張）
