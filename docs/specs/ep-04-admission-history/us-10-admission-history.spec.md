## ユーザーストーリー

- **As a** 病棟事務
- **I want** 患者の入退院履歴を参照・更新し、入院形態変更や入退院取消の是正操作も同一画面で行いたい
- **So that** オーダ起点の自動取り込みを基本としつつ、例外時には履歴を正しく保てる

## 振る舞い

- **患者選択 + 入院時タブ**: 当該患者の最新入院期間 / initial 形態レコードが選択された状態で開く
- **左ペイン形態レコードクリック**: 右ペインに詳細表示、上部タブ（入院時/退院時）に応じてフォーム切替
- **入院時／退院時タブ切替**: 同じ形態レコードに対して、入院時情報か退院時情報を表示
- **登録ボタン**: 入院決定理由・退院決定理由・退院後処置・帰住先の更新を保存（モックではスナックバー通知 + dynamicMedicalRecords に記事追加）
- **形態変更ボタン**: 入院形態変更ダイアログを開く。最新形態（current）レコードのみ可
  - 登録時: 旧形態レコードの dischargeDate に「新形態の admitDate - 1 分」を設定し、新しい形態レコードを追加
  - 診療録（dynamicMedicalRecords）に「入院形態変更」記事を追加
- **変更取消ボタン**: 形態変更レコード（initial 以外）に表示。クリック時:
  1. 削除コメントダイアログで分類 + 理由入力
  2. 確定で形態変更レコード削除、旧形態レコードの dischargeDate を元に戻す
  3. 診療録に取消記事を追加
  - ※以前あった「入院時文書追加チェック → 削除確認」は取り扱わないため削除（2026-08-17）
- **入院取消ボタン**: 直近入院歴 + 現在入院中で表示
  1. 入院固有オーダ（入院定時・行動範囲等）残留チェック → 残っていれば取消不可警告
  2. 削除コメントダイアログで分類 + 理由
  3. 確定で当該入院期間のレコード一式削除、入院確定オーダ・食事療法も連動取消
  - ※以前あった「入院時文書削除確認」は取り扱わないため削除（2026-08-17）
- **退院取消ボタン**: 直近退院歴で表示
  1. 削除コメントダイアログで分類 + 理由
  - ※以前あった「退院時文書削除確認」は取り扱わないため削除（2026-08-17）
  3. 確定で当該退院レコード削除（status を「入院中」に戻す）
- **関連履歴リンク**:
  - 食事歴: モックではスナックバー通知（実装エピック未割当）
  - 移動歴: `/admission` タブ「移動歴」に切替
  - 隔離歴: モックではスナックバー通知（ep-08 で本実装）

## 受け入れ基準（AC）

- [ ] **AC-1: 入院歴／退院歴をタブ切替で参照できる**
  - **Given** 患者の入院歴画面を開いている
  - **When** 入院時／退院時タブを切り替える
  - **Then** それぞれ入院日・指示医・病棟・入院形態・入院決定の理由（入院時）／退院日・指示医・退院区分・転帰・退院決定の理由・退院後処置・帰住先（退院時）が表示される。初期表示時は最新の入院歴が選択される

- [ ] **AC-2: 履歴一覧から詳細を表示できる**
  - **Given** 入院歴画面を開いている
  - **When** 左側の入院履歴（期間のリンク）をクリックする
  - **Then** 右側に当該期間の詳細情報が表示される（入院日・形態変更日の昇順、最新が画面最下部）

- [ ] **AC-3: オーダ確定で履歴が自動生成される**
  - **Given** 入退院指示が確定し入退院手続きが完了している
  - **When** 自動連携が実行される
  - **Then** 入院歴に対応するレコードが自動追加される

- [ ] **AC-4: 入院決定理由・退院決定理由を更新できる**
  - **Given** 入院歴画面を開いている
  - **When** 入院決定の理由／退院決定の理由を編集して [登録] をクリックする
  - **Then** 内容が更新される（最大3000文字、変更日時・操作者が記録される）

- [ ] **AC-5: 退院後処置・帰住先を更新できる**
  - **Given** 退院時タブを表示している
  - **When** 退院後処置（最大1000文字）または帰住先（住居区分マスタ参照）を入力し [登録] する
  - **Then** 内容が更新される

- [ ] **AC-6: 入院形態変更を追加できる**
  - **Given** 最新の入院歴を選択している
  - **When** [形態変更] をクリックして入院情報編集モードで新しい入院形態と移動日時を設定し [登録] する
  - **Then** 入院形態変更が新たな履歴として追加され、前形態の最終日（移動日）は形態変更日時の1分前が自動設定される。診療録にも履歴が作成される

- [ ] **AC-7: 入院形態変更の日時を更新できる（現在入院中のみ）**
  - **Given** 現在入院中の患者で、入退院日以外の入院歴を選択している
  - **When** 入院日（形態変更日時）を編集して [登録] する
  - **Then** 形態変更日時が更新される（入退院日自体は変更不可）

- [ ] **AC-8: 入院形態変更を取り消せる**
  - **Given** 入院形態変更の入院歴を選択している
  - **When** [変更取消] をクリックする
  - **Then** 削除コメントダイアログで分類と理由を入力すると形態変更が取り消される。診療録にも取消記事が記載される（入院時文書は取り扱わないため文書削除確認は無し・2026-08-17）

- [ ] **AC-9: 入院取消・退院取消ができる（直近入院歴のみ）**
  - **Given** 直近の入院歴を表示している（現在入院中）
  - **When** [入院取消] または [退院取消] をクリックする
  - **Then** 削除コメントダイアログで理由を入力すると取り消される。入院確定オーダ・食事療法は連動して取り消される（入院時文書／退院時文書は取り扱わないため文書削除確認は無し・2026-08-17）

- [ ] **AC-10: 入院固有オーダがある場合は取消前に削除が必要**
  - **Given** 患者に入院定時・行動範囲等の入院固有オーダが残っている
  - **When** 入院取消を実行しようとする
  - **Then** 取消は実行できず、先に該当オーダを削除する必要がある

- [ ] **AC-11: 関連履歴へ遷移できる**
  - **Given** 入院歴画面を開いている
  - **When** 食事歴／移動歴／隔離歴のリンクを選択する
  - **Then** 該当履歴画面に遷移する

## 状態遷移 / バリデーション

- 入院歴レコード状態: `current 形態` / `形態変更前` / `退院済`
- 形態変更可否: current 形態のみ可
- 変更取消可否: 形態変更レコード（initial 以外）のみ可
- 入院取消可否: 直近入院歴 + 現在入院中 + 入院固有オーダ残留なし
- 退院取消可否: 直近退院歴 + 当該患者の現在ステータスが「退院済」
- 入院決定理由・退院決定理由: 最大 3000 文字
- 退院後処置: 最大 1000 文字
- 帰住先: 住居区分マスタから選択（モックは固定セット）

## 補足

- 取消・形態変更時の削除コメント分類はマスタで管理（ep-03 で導入済 `DELETE_REASON_CATEGORIES` を再利用）
- **入院時文書・退院時文書（期限管理文書）は現時点では電子カルテで取り扱わないため、本仕様から除外（2026-08-17）**。以前あった「取消時の文書削除確認」「事前ダウンロードの注意喚起」「形態変更時の入院時文書チェック（`ADMIT_DOCS_BY_FORM` 再利用）」は UI・データとも削除済み。
- 外部精神科システム連携時の追加項目（精神科入院有無・問診結果・退院後の所在）は `useAppStore.optionalFeatures.psychiatricLink` で表示分岐
