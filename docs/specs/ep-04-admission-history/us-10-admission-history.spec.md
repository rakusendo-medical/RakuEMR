## ユーザーストーリー

- **As a** 病棟事務
- **I want** 患者の入退院履歴を参照・更新し、入院形態変更や入退院取消の是正操作も同一画面で行いたい
- **So that** オーダ起点の自動取り込みを基本としつつ、例外時には履歴を正しく保てる

> **入院形態変更の位置づけ**: 入院形態変更は「退院」ではなく、**入院を継続したまま今の入院形態（任意/医療保護/措置 等）を別の形態に切り替える**操作。一度退院して再入院するわけではない（詳細は補足）。

## 振る舞い

- **患者選択 + 入院時タブ**: 当該患者の最新入院期間 / initial 形態レコードが選択された状態で開く
- **左ペイン形態レコードクリック**: 右ペインに詳細表示、上部タブ（入院時/退院時）に応じてフォーム切替
- **入院時／退院時タブ切替**: 同じ形態レコードに対して、入院時情報か退院時情報を表示
- **登録ボタン**: 入院決定理由・退院決定理由・退院後処置・帰住先の更新を保存（モックではスナックバー通知 + dynamicMedicalRecords に記事追加）
- **形態変更ボタン**: 入院形態変更ダイアログを開く。最新形態（current）レコードのみ可
  - **入院形態変更の意味**: これは**退院ではなく、入院を継続したまま「今の入院形態」を別の形態（任意/医療保護/措置 等）に切り替える**操作である。患者は在院のまま、形態（区分）だけが切り替わる（一度退院して再入院するわけではない）
  - 登録時: 旧形態レコードの dischargeDate に「新形態の admitDate - 1 分」を設定し、新しい形態レコードを追加
  - 診療録（dynamicMedicalRecords）に「入院形態変更」記事を追加
- **変更取消ボタン**: 形態変更レコード（initial 以外）に表示。クリック時:
  1. 削除コメントダイアログで分類 + 理由入力
  2. 確定で形態変更レコード削除、旧形態レコードの dischargeDate を元に戻す
  3. 診療録に取消記事を追加
  - ※以前あった「入院時文書追加チェック → 削除確認」は取り扱わないため削除（2026-08-17）
- **入院取消ボタン**: 直近入院歴の現形態（継続中）レコード + 現在入院中（退院済でない）で表示。取消済の期間では登録・形態変更・変更取消・入院取消・退院取消をすべて出さない（履歴として参照のみ）
  1. 入院固有オーダ（入院定時・行動範囲等）残留チェック → 残っていれば取消不可警告
  2. 削除コメントダイアログで分類 + 理由
  3. 確定で当該入院期間の全形態レコードを取消済（`status: 'キャンセル'`）にし、取消日時・分類・理由を保持する（**物理削除しない**）。入院確定オーダ・食事療法も連動取消
  4. 分類が「入力誤り」（操作ミス）なら入院歴一覧に出さない／それ以外は [取消済] として一覧に残す
  - ※以前あった「入院時文書削除確認」は取り扱わないため削除（2026-08-17）
- **退院取消ボタン**: 直近退院歴で表示
  1. 削除コメントダイアログで分類 + 理由
  - ※以前あった「退院時文書削除確認」は取り扱わないため削除（2026-08-17）
  3. 確定で当該退院レコード削除（status を「入院中」に戻す）
- **関連履歴リンク**:
  - 食事歴: モックではスナックバー通知（実装エピック未割当）
  - 移動歴: `/admission` タブ「移動歴」に切替
  - 隔離歴: モックではスナックバー通知（ep-08 で本実装）

## 受け入れ基準（AC）

- [ ] **AC-1: 入院歴／退院歴をタブ切替で参照できる**
  - **Given** 患者の入院歴画面を開いている
  - **When** 入院時／退院時タブを切り替える
  - **Then** それぞれ入院日・指示医・病棟・入院形態・入院決定の理由（入院時）／退院日・指示医・退院区分・転帰・退院決定の理由・退院後処置・帰住先（退院時）が表示される。初期表示時は最新の入院歴が選択される

- [ ] **AC-2: 履歴一覧から詳細を表示できる**
  - **Given** 入院歴画面を開いている
  - **When** 左側の入院履歴（期間のリンク）をクリックする
  - **Then** 右側に当該期間の詳細情報が表示される（入院日・形態変更日の昇順、最新が画面最下部）

- [ ] **AC-3: オーダ確定で履歴が自動生成される**
  - **Given** 入退院指示が確定し入退院手続きが完了している
  - **When** 自動連携が実行される
  - **Then** 入院歴に対応するレコードが自動追加される

- [ ] **AC-4: 入院決定理由・退院決定理由を更新できる**
  - **Given** 入院歴画面を開いている
  - **When** 入院決定の理由／退院決定の理由を編集して [登録] をクリックする
  - **Then** 内容が更新される（最大3000文字、変更日時・操作者が記録される）

- [ ] **AC-5: 退院後処置・帰住先を更新できる**
  - **Given** 退院時タブを表示している
  - **When** 退院後処置（最大1000文字）または帰住先（住居区分マスタ参照）を入力し [登録] する
  - **Then** 内容が更新される

- [ ] **AC-6: 入院形態変更を追加できる**
  - **Given** 最新の入院歴を選択している
  - **When** [形態変更] をクリックして入院情報編集モードで新しい入院形態と移動日時を設定し [登録] する
  - **Then** 入院形態変更が新たな履歴として追加され、前形態の最終日（移動日）は形態変更日時の1分前が自動設定される。診療録にも履歴が作成される

- [ ] **AC-7: 入院形態変更の日時を更新できる（現在入院中のみ）**
  - **Given** 現在入院中の患者で、入退院日以外の入院歴を選択している
  - **When** 入院日（形態変更日時）を編集して [登録] する
  - **Then** 形態変更日時が更新される（入退院日自体は変更不可）

- [ ] **AC-8: 入院形態変更を取り消せる**
  - **Given** 入院形態変更の入院歴を選択している
  - **When** [変更取消] をクリックする
  - **Then** 削除コメントダイアログで分類と理由を入力すると形態変更が取り消される。診療録にも取消記事が記載される（入院時文書は取り扱わないため文書削除確認は無し・2026-08-17）

- [ ] **AC-9: 入院取消・退院取消ができる（直近入院歴のみ）**
  - **Given** 直近の入院歴を表示している（現在入院中）
  - **When** [入院取消] または [退院取消] をクリックする
  - **Then** 削除コメントダイアログで理由を入力すると取り消される。入院確定オーダ・食事療法は連動して取り消される（入院時文書／退院時文書は取り扱わないため文書削除確認は無し・2026-08-17）

- [ ] **AC-9b: 入院取消した入院歴はデータとして残り、理由分類で一覧表示が変わる**
  - **Given** 入院取消を実行した入院歴がある
  - **When** 入院歴一覧を表示する
  - **Then** 削除理由分類が **「入力誤り」（操作ミス）** の場合は**一覧に表示しない**。それ以外の分類（医師判断による中止／患者意向による中止／システム障害／その他）は**一覧に表示する**（期間見出しに [取消済] チップ、形態レコードに [取消] チップ）。いずれの場合もレコードは保持し、物理削除しない

- [ ] **AC-9c: 取消済の入院歴は参照のみで、取消内容が分かる**
  - **Given** 取消済として一覧に残っている入院期間を選択している
  - **When** 詳細を表示する
  - **Then** [登録][形態変更][変更取消][入院取消][退院取消] はいずれも表示されず、代わりに**取消内容（取消日時・分類・理由）と「参照のみ」である旨**が表示される。編集項目（入院/退院決定の理由・転帰・退院後処置・帰住先）は入力不可になり、「現在の形態」「現在」バッジは付かず [取消済]／[取消] として表示される

- [ ] **AC-10: 入院固有オーダがある場合は取消前に削除が必要**
  - **Given** 患者に入院定時・行動範囲等の入院固有オーダが残っている
  - **When** 入院取消を実行しようとする
  - **Then** 取消は実行できず、先に該当オーダを削除する必要がある

- [ ] **AC-11: 関連履歴へ遷移できる**
  - **Given** 入院歴画面を開いている
  - **When** 食事歴／移動歴／隔離歴のリンクを選択する
  - **Then** 該当履歴画面に遷移する

## 状態遷移 / バリデーション

- 入院歴レコード状態: `current 形態` / `形態変更前` / `退院済`
- **入院形態が終わるタイミング（形態レコードの `dischargeDate` が確定する条件）**:
  - **① 形態変更**: 次の形態へ切り替えたとき終わる。終了時刻＝**形態変更日時の 1 分前**（＝新形態の `admitDate − 1 分`）。旧形態の `dischargeDate` にこの値を設定する。※変更取消でこの終了は取り消し（`dischargeDate` を未設定に戻す）
  - **② 退院**: 退院手続きで終わる。終了時刻＝**退院日時**（期間内で最後のレコードの `dischargeDate`＝実際の退院日時）
  - **③（入院取消）**: 入院そのものを取り消す操作のため、形態の「終了」ではなく**取消**。期間内の全形態レコードを `status: 'キャンセル'` にし、物理削除はしない（一覧に出すかは削除理由分類による→補足「入院取消の可否と取消データの扱い」）
  - `dischargeDate` 未設定＝「現在（継続中）」。①で閉じられた（期間内で最後でない）ものは「退院」ではなく**形態の終了（次形態への切替）**であり、退院と区別して表記する（→退院時タブは「形態終了日時」、左リストは「に形態変更」）
- 形態変更可否: current 形態のみ可
- 変更取消可否: 形態変更レコード（initial 以外）のみ可
- 入院取消可否: 直近入院歴の**現形態（継続中＝`dischargeDate` 未設定）のレコード** + 現在入院中（退院済でない）+ 入院固有オーダ残留なし + 当該期間が取消済でない
  - **最初の形態レコードに限定しない**。形態変更を 1 度でも行った患者は最初のレコードが形態変更で閉じられているため、限定すると入院中でも取り消せなくなる（参考システムは「現在入院中なら直近の入院歴で取消可能」）。形態変更で閉じられたレコードでは出さない点は issue #486 のとおり
  - 「入院中か」はレコードの `status` ではなく「退院済のレコードが無いこと」で判定する（取消情報を伴わない `status: 'キャンセル'` が残っても影響を受けないようにするため）
  - 参考システムでも入院取消は入院歴画面で行い、「現在入院中の場合のみ表示」「直近の入院歴（〜現在入院中）のみ取消可能」（参考: 基本システム 第2章 患者情報「８．入院歴・退院歴 ・入院取消、退院取消」）
- 入院取消後の一覧表示: 削除理由分類が「入力誤り」なら一覧に出さない／それ以外は取消済として一覧に出す（レコードは常に保持）
- 取消済の期間: 登録・形態変更・変更取消・入院取消・退院取消をすべて出さない（参照のみ）。編集項目は入力不可。取消済は「現在（継続中）」ではないため、期間・形態レコード・詳細ヘッダーのいずれにも「現在」系バッジを出さず [取消済]／[取消] を表示する
- 退院取消可否: 直近退院歴 + 当該患者の現在ステータスが「退院済」
- 入院決定理由・退院決定理由: 最大 3000 文字
- 退院後処置: 最大 1000 文字
- 帰住先: 住居区分マスタから選択（モックは固定セット）

## 補足

- **入院形態変更は「退院」ではない（issue #486・2026-09-04）**: 形態変更は**入院を継続したまま入院形態（任意/医療保護/措置 等）を切り替える**記録であり、物理的な退院・再入院ではない。実装では旧形態レコードの `dischargeDate` に「形態変更日時 − 1 分」を設定するが、これは**その形態の終了（次形態への切替時刻）**を表す内部表現。誤解を避けるため、退院時タブの退院日は**形態変更で閉じられたレコード（期間内で最後でない＝初期入院レコード含む）**で→「形態終了日時」（＋「退院ではない」補足）に切り替える。入院日は形態変更レコードでも「入院日」のまま（その形態の開始日＝参考システムでも入院日として表示）。タブ名は常に「入院時/退院時」。参考システムでも形態変更は「前形態が履歴になり変更日時を入院日として新形態が開始」する扱い（参考: 基本システム 第2章 患者情報「入院形態変更」）。
- **「現在」バッジは最新形態のみ（issue #486・2026-09-04）**: 各形態レコードは `dischargeDate` 未設定＝「現在（継続中）」と判定する。2 回目以降の形態変更で旧形態（＝過去に追加した形態レコード）へ設定する終了日時が反映されず複数の形態に「現在」が付く不具合があったため、**追加レコードにも編集差分（`admissionHistoryEdits`）をマージ**するよう修正。これにより現在バッジは最新の 1 形態のみに付く。
- **入退院記録（診療録記事）の作成条件（issue #427・2026-09-04）**: 入院歴画面の操作は、カルテ診療録の **category「入退院記録」の記事**（store の `dynamicMedicalRecords`。author＝指示医）を `appendMedicalRecord` で作成する。作成される操作は以下:
  - **登録**（AC-4/5 の入院時/退院時の理由等の更新。AC-7 の形態変更日時更新も同じ [登録]）→ タグ「入院歴更新」
  - **形態変更**（AC-6）→ タグ「形態変更」
  - **変更取消**（AC-8）→ タグ「形態変更取消」
  - **退院取消**（AC-9）→ タグ「退院取消」
  - **入院取消**（AC-9）→ タグ「入院取消」。入院歴レコードも残す（下記「入院取消の可否と取消データの扱い」で確定）。ただし削除理由分類が「入力誤り」の場合、入院歴一覧には出さない
  - 記事の中身: 操作内容・形態・分類/理由（取消系）等を content に記載。`dynamicMedicalRecords` は非永続のためリロードで消える（モックのためセッション限定）
- **入院取消の可否と取消データの扱い（管理者確認・2026-09-04／issue #427）**: 運用ルールとして以下が確定した。
  - **入院取消は入院歴画面で行う**（参考システムでも同様）。**現在入院中**かつ**直近の入院歴の現形態（継続中）レコード**でのみ実行でき、入院固有オーダが残っている場合は先に削除が必要
  - **入力ミス（削除理由分類「入力誤り」）による入院取消**: データとしては残すが、**入院歴一覧には表示しない**。誤登録は運用上「無かったこと」として扱うため
  - **入力ミス以外の理由による入院取消**（医師判断による中止／患者意向による中止／システム障害／その他）: **入院歴一覧に表示する**。実際に入院があり取り消された事実として残す必要があるため
  - いずれの場合もレコードは物理削除しない（監査・履歴目的）。「一覧に出す／出さない」は表示制御であり、データ保持とは独立
  - **実装（2026-09-04）**: 取消時は `removeAdmissionHistory`（物理削除）をやめ、期間内の全レコードを `editAdmissionHistory` で `status: 'キャンセル'` にしたうえで、`useAppStore.cancelAdmissionPeriod(periodId, { cancelledAt, category, reason })` に取消情報を保持する（`admissionCancellations`。永続化対象）。入院歴一覧は分類が「入力誤り」の期間だけ除外し、それ以外の取消済期間は期間見出しに [取消済] チップ（取消日時・分類・理由を tooltip 表示）を付けて残す
  - **取消済の見せ方**: 操作ボタンを消すだけだと詳細ペインの操作エリアが空欄になり状況が読めないため、取消内容（取消日時・分類・理由）と「参照のみ」である旨のパネルを表示する。あわせて編集項目を入力不可にし、「現在の形態」「現在」バッジと「継続中」表記は出さず [取消済]／[取消] に置き換える
  - **永続データの移行**: 取消は永続化対象（`admissionCancellations`）。取消情報を伴わない `status: 'キャンセル'` の編集差分が残っていると入院取消ボタンが出なくなるため、store の永続化バージョンを 4 に上げて移行時に掃除する
- 取消・形態変更時の削除コメント分類はマスタで管理（ep-03 で導入済 `DELETE_REASON_CATEGORIES` を再利用）
- **入院時文書・退院時文書（期限管理文書）は現時点では電子カルテで取り扱わないため、本仕様から除外（2026-08-17）**。以前あった「取消時の文書削除確認」「事前ダウンロードの注意喚起」「形態変更時の入院時文書チェック（`ADMIT_DOCS_BY_FORM` 再利用）」は UI・データとも削除済み。
- 外部精神科システム連携時の追加項目（精神科入院有無・問診結果・退院後の所在）は `useAppStore.optionalFeatures.psychiatricLink` で表示分岐
