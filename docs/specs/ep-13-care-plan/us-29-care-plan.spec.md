## ユーザーストーリー

- **As a** 受け持ち看護師
- **I want** 看護計画の長期目標を期間単位で新規作成・更新・削除し、配下に複数の明細を登録・更新・削除したい
- **So that** 患者の状態に応じた計画を構造化して保持し、明細単位で柔軟に運用できる

## 画面要素（要素ツリー）

```
- 看護計画画面 (/care-plan/patients/:patientId)
  - ヘッダー: 患者基本情報サマリ（患者番号・氏名・年齢・性別・病棟・主治医）
  - 計画選択バー

  - タブ
    - 問題点タブ（メイン、本ストーリー対象）
    - アセスメントタブ（参考、別エピック）
  - 看護経過記録の作成リンク（[看護経過記録]）

  - 優先度セレクト（必須）
  - 看護診断セレクト＋検索ボタン（必須）
  - 短期目標テキスト（必須）
```

## 振る舞い

- **画面初期表示**: 期間プルダウンに既存計画一覧（最新期間が先頭）+「新規」を表示。最新の active 計画があればそれを表示
- **期間プルダウン変更 → [表示]**: 当該計画の長期目標と明細が表示される
- **期間プルダウン「新規」 → [保守]**: 看護計画新規入力ダイアログを開く
- **期間プルダウン既存 → [保守]**: 看護計画編集ダイアログを開く
- **新規入力 [登録]**:
  - 期間開始日 < 既存計画の期間と重複する場合 → エラー表示「同期間の看護計画が既に存在します」
  - 重複なし → 看護計画として登録、期間プルダウンに追加、登録後の計画を画面に表示
- **継続中チェック ON → OFF**: 終了日入力欄が活性化、必須化
- **「前回の計画を引き継ぐ」ON で [登録]**: 前回計画の長期目標 + 全明細をコピーして新規作成
- **編集 [更新]**: 内容反映、変更日時・操作者を更新履歴に記録
- **編集 [削除]**: 看護計画削除（履歴は保持）
- **明細 [新規追加]**: 明細新規入力ダイアログを起動、登録で計画明細追加
- **明細 [テンプレートより追加]**: テンプレート選択ダイアログ → 選択した明細を計画に複写
- **明細 [看護診断より追加]**: 看護診断ダイアログ [ep-12] → 適用日指定で明細生成
- **明細番号クリック**: 看護計画明細修正ダイアログを開く
- **明細修正 [更新] / [削除]**: 当該明細を更新／削除
- **[並び替え]**: 並び替えダイアログ → [更新] で表示順を保存
- **[看護経過記録]**: 看護経過記録ダイアログを開く（ep-10 の NursingRecordDialog 共有）
  - 形式 FOCUS のとき: タイトル欄に「明細 No と診断名」、A欄に介入を自動セット
  - 同看護計画コンテキストの場合は自動関連付け
- **計画明細の最終評価日リンク**: 評価画面 [ep-14]（`/care-plan/patients/:patientId/evaluate?problemItemId=...`）へ遷移

## 受け入れ基準（AC）

- [ ] **AC-1: 看護計画画面で対象計画を切替表示できる**
  - **Given** 看護計画画面の問題点タブを開いている
  - **When** 期間プルダウンから対象計画を選択し [表示] をクリックする
  - **Then** 当該計画の長期目標と明細が表示される

- [ ] **AC-2: 長期目標を新規作成できる**
  - **Given** 看護計画画面を開いている
  - **When** 期間プルダウンで「新規」を選択し [保守] をクリックして看護計画新規入力ダイアログを開き、期間開始日・長期目標・ラベルパターン（1または2）を入力して [登録] する
  - **Then** 看護計画として登録され、期間プルダウンに追加される

- [ ] **AC-3: 継続中・終了日を制御できる**
  - **Given** 看護計画新規入力ダイアログを開いている
  - **When** 継続中チェックを操作する
  - **Then** 継続中チェック有り: 終了日入力不要。継続中チェック無し: 終了日入力欄が活性化、終了日を指定して登録

- [ ] **AC-4: 前回の計画を引き継いで作成できる**
  - **Given** 看護計画の履歴が存在する患者で新規入力ダイアログを開いている
  - **When** 「前回の計画を引き継ぐ」チェックを操作して [登録] する
  - **Then** 前回計画の内容（長期目標・明細）がすべてコピーされる

- [ ] **AC-5: 長期目標を更新できる**
  - **Given** 既存の長期目標を表示している
  - **When** [保守] をクリックして看護計画編集ダイアログを開き、内容を編集して [更新] する
  - **Then** 更新が反映され、変更日時・操作者が記録される

- [ ] **AC-6: 長期目標を削除できる**
  - **Given** 既存の長期目標を表示している
  - **When** 看護計画編集ダイアログで [削除] をクリックする
  - **Then** 計画が削除される（履歴は保持）

- [ ] **AC-7: 同一期間に複数計画を立てられない**
  - **Given** 既に同期間の看護計画が存在する
  - **When** 同期間で新たな計画を保存しようとする
  - **Then** 期間重複エラーが表示され保存されない

- [ ] **AC-8: 明細を追加できる（3つの追加方式）**
  - **Given** 長期目標を選択している
  - **When** [新規追加]／[テンプレートより追加]／[看護診断より追加] のいずれかをクリックする
  - **Then** それぞれの方式で計画明細が追加できる
    - [新規追加]: 看護計画明細新規入力ダイアログ
    - [テンプレートより追加]: 看護計画テンプレート選択ダイアログ
    - [看護診断より追加]: 看護診断ダイアログ [ep-12] から連携

- [ ] **AC-9: 明細を更新できる**
  - **Given** 計画明細が登録されている
  - **When** 明細番号をクリックして看護計画明細修正ダイアログで内容を変更し [更新] する
  - **Then** 当該明細が更新される

- [ ] **AC-10: 明細を削除できる**
  - **Given** 計画明細が登録されている
  - **When** 看護計画明細修正ダイアログで [削除] する
  - **Then** 当該明細が削除される

- [ ] **AC-11: 明細を並び替えできる**
  - **Given** 複数明細が登録されている
  - **When** 並び替えダイアログで順序を変更する
  - **Then** 表示順が更新される

- [ ] **AC-12: 看護経過記録を看護計画から作成できる**
  - **Given** 看護計画画面を表示している
  - **When** [看護経過記録] をクリックする
  - **Then** 看護経過記録ダイアログがFOCUS形式の場合タイトルに「No と診断」、A欄に介入が自動設定される。同看護計画の場合は自動的に関連付けが行われる

- [ ] **AC-13: 評価画面に遷移できる**
  - **Given** 計画明細を表示している
  - **When** 計画明細の問題点欄下に表示される最終評価日（または「評価無し」）をクリックする
  - **Then** 当該計画の評価画面（[ep-14]）が開かれる

## 状態遷移 / バリデーション

- 期間重複の判定:
  - 既存計画の期間 = `[periodStart, periodEnd（継続中なら ∞）]`
  - 新規計画の期間 = `[newStart, newEnd]`
  - 重複 = 既存と新規の期間が重なる（同日終了→同日開始の境界扱いは実装時確定。spec 既定では境界含む）
- 継続中チェック有: `periodEnd = undefined`、終了日入力不可
- 継続中チェック無: `periodEnd` 必須
- ラベルパターンによって各計画タイトルの名称表示が変わる（パターン1／2、マスタ管理）
- 「前回の計画を引き継ぐ」: 直前の閉じた（または現在の）計画から長期目標 + 全明細をコピー

## 補足

- 医療観察法対象患者の場合は別途レイアウト・項目があるが本ストーリーは一般患者を対象（オプション機能 `optionalFeatures.medicalProtection` 連動は別ラウンド）
- 明細番号の付番ルールは作成順（追加時連番）。並び替えしても番号は固定
- 既存実装（`src/features/carePlan/`）からの主な変更点:
  - `CarePlan` に `periodStart` / `periodEnd?` / `labelPattern: 1 | 2` / `isOngoing: boolean` 追加
  - 単一 active 計画前提を撤廃（patientId × periodStart で一意）
  - PatientCarePlan ページの「期間プルダウン → [表示] / [保守]」UI 構築
  - MonthlyEvaluation 画面は廃止し、計画明細毎の評価導線へ移行（[ep-14]）
- spec 準拠の再設計は既存実装のリファクタを伴う。実装着手前に PM 経由で範囲確認すること
