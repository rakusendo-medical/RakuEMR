## ユーザーストーリー

- **As a** 病棟看護師長
- **I want** 病棟マップ上で患者の病床を別の病床に移動したい
- **So that** 病室変更や病棟間移動を、紙運用や事務連絡を介さずに即時反映できる

## 画面要素（要素ツリー）

```
- 病棟マップ画面（us-01参照）
  - フッター領域
    - 患者操作メニュー（患者選択時）
      - 操作リンク群
        - 移動リンク: クリックで転棟・転室ダイアログを新規モードで開く
        - 移動アイコン (移動予定が登録済の場合): ベッドマス上にも表示
- 転棟・転室ダイアログ
  - ヘッダー
    - 患者基本情報: 氏名・年齢・性別・現在の病棟/病室/ベッド
    - モード表示: 新規登録 / 履歴選択中
  - 移動先入力フォーム
    - 病棟セレクト: 初期表示は現病棟（同一病棟も可）
    - 病室セレクト: 選択病棟内の病室
    - 移動日時入力: 日付 + 時刻、未来日時可
    - 配膳先変更日時入力: 食事配膳先の切替日時
    - 隔離・拘束チェック群 (オーダリング運用時のみ表示): 移動と同時に登録
  - 履歴欄
    - 既登録移動リスト: この患者の登録済み移動を一覧
      - 履歴行 × N: 日時・移動元・移動先・状態（予定／移動済／取消）
        - 選択操作: クリックでフォームに値を読み込み、更新モードへ（削除は不可）
        - [取消] ボタン（取消していない行のみ）: 確認の上、当該移動を取消状態にする（削除ではない）
  - 印刷オプション
    - 移動箋チェック (マスタで有効時)
    - 食事箋チェック (マスタで有効時)
  - フッターアクション
    - 登録ボタン (新規モード)
    - 更新ボタン (履歴選択時)
    - キャンセルボタン
- 確認ダイアログ群
  - 食事締め時間超過確認 (移動日時が締め時間を過ぎている場合): OK / キャンセル
```

## 振る舞い

- **移動リンククリック**: 転棟・転室ダイアログを新規モードで開く
- **病棟→病室の段階セレクト**: 病棟選択で病室の選択肢を絞り込む。ベッド指定は廃止（布団運用）＝移動先は病室まで指定し、病室内の空き枠へ自動割当する
- **移動日時=未来**: 登録後、移動予定時刻まで患者は移動元に在床表示。ベッドマスに移動アイコン付与
- **移動日時=現在/過去**: 即時反映、移動元は空床に変更
- **不在者（外出・外泊中）の移動**: 通常と同様に登録できる
- **履歴選択**: 既登録の移動をフォームに読み込み、更新可能。**削除は不可**（参考システムは移動済みでも削除可だが、当院運用では削除不可とする）
- **取消**: 履歴行の [取消] → 確認 → 当該移動を「取消」状態にする。履歴からは消えず**取消として残る**（削除ではない）。取消状態の行は [取消] を出さない
  - 取消した移動が **移動済**（移動日時が過去）の場合: 患者を**移動前の病室へ戻す**（移動元病室の空き枠へ自動割当。空きが無ければ戻さずスキップ）
  - 取消した移動が **予定**（移動日時が未来・未実施）の場合: 病室は動かさず、取消履歴のみ残す
- **食事締め時間超過時の登録／更新**: 確認ダイアログを挟む（OK で続行）
- **オーダリング運用時**: 隔離・拘束チェック項目を追加表示

## 受け入れ基準（AC）

- [ ] **AC-1: 患者を選択して移動ダイアログを開ける**
  - **Given** 病棟マップで在床患者の氏名をクリックしている
  - **When** 操作リンクから「移動」を選択する
  - **Then** 転棟・転室ダイアログが新規登録モードで開かれる

- [ ] **AC-2: 移動先の病室を変更できる**
  - **Given** 転棟・転室ダイアログを表示している
  - **When** 移動先の病棟（初期表示は現病棟）・病室と移動日時、配膳先変更日時を入力し登録する
  - **Then** 患者が移動先の病室に変更され（病室内の空き枠へ自動割当）、移動元は空床になる

- [ ] **AC-3: 未来日の移動（移動予定）が登録できる**
  - **Given** 移動日時に未来日時を指定して登録している
  - **When** 移動予定時刻に至っていない
  - **Then** 患者は移動前の病床に表示され続け、移動アイコンが付与される。移動予定時刻経過後に病棟マップを再表示すると、移動先病床に反映される

- [ ] **AC-4: 不在者（外出・外泊中）も移動登録できる**
  - **Given** 患者が外出・外泊中である
  - **When** 移動操作を実行する
  - **Then** 通常と同様に移動登録できる

- [ ] **AC-5: 移動内容を変更できる（削除は不可）**
  - **Given** 既存の移動情報を再表示している
  - **When** ダイアログ履歴欄から対象の移動を選択し更新を実行する
  - **Then** 該当移動が更新され、ダイアログが閉じて病棟マップに反映される

- [ ] **AC-6: 移動履歴は削除できない**
  - **Given** 移動履歴（移動前・移動済みを問わず）を表示している
  - **When** 履歴行を選択する
  - **Then** 削除の操作・ボタンは提供されない（参考システムは移動済みでも削除可だが、当院運用では削除不可）。削除の代替として「取消」を用いる（別途対応）

- [ ] **AC-7: 食事締め時間を過ぎた登録・更新では確認が出る**
  - **Given** 食事締め時間を過ぎた状態で登録または更新を実行する
  - **When** 確定操作を行う
  - **Then** 確認メッセージが表示され、OK で続行できる

- [ ] **AC-8: オーダリング運用時は隔離・拘束チェックが追加される**
  - **Given** オーダリング運用時に転棟・転室ダイアログを開いている
  - **When** ダイアログを表示する
  - **Then** 隔離・拘束の登録用チェック項目が追加で表示される

- [ ] **AC-9: 移動を取消でき、履歴に取消として残る**
  - **Given** 移動履歴に取消可能な移動（予定または移動済）がある
  - **When** 履歴行の [取消] を実行し確認する
  - **Then** 該当移動が「取消」状態になり、履歴からは削除されず取消として残る（以後 [取消] は非表示）

- [ ] **AC-10: 移動済の取消で移動前の病室へ戻る**
  - **Given** 移動済（移動日時が過去）の移動履歴がある
  - **When** その行を [取消] する
  - **Then** 患者が移動前の病室（移動元）へ戻り、病棟マップに反映される（移動元病室に空き枠が無ければ戻さない）

## 状態遷移 / バリデーション

- ダイアログモード: 新規 → 登録完了 → 閉じる / 履歴選択 → 更新 → 閉じる（削除モードは無し）
- 移動状態: 予定（移動日時が未来）／移動済（過去）／取消（[取消] 実行済み）。取消は削除ではなく履歴に残る
- 移動日時 < 現在: 即時反映、移動アイコン無し
- 移動日時 ≥ 現在: 移動予定、移動アイコン付与、時刻経過で自動切替
- 食事締め時間 < 移動日時 ≤ 現在: 確認ダイアログ
- 移動先病室に空き枠が無い場合: 登録不可（別の病室を選択）

## 補足

- 指示箋（移動箋・食事箋）の表示有無・名称・帳票レイアウトはマスタ設定。本モックではチェック UI のみ実装でよい（削除不可のため「移動削除箋」は設けない）
- 移動の理由区分（治療都合・本人都合等）の入力要否は別途検討
- 「再度別の病室に移動する場合は変更ではなく新規登録」が運用ルール。UI上の誘導要否は別途検討
- ベッド指定は廃止（当院はベッドではなく布団運用のため）。移動先は「病棟（初期表示は現病棟）＋病室」まで指定し、モックデータ上のベッド枠へは病室内の空き先頭を自動割当する。移動先病室に空き枠が無い場合は登録不可
- 移動履歴の削除は不可（参考システムは移動済みでも削除できるが、当院運用では削除ボタン・削除モード・移動削除箋を設けない）。削除の代替として「取消」を用いる（AC-9。履歴に取消状態で残す）
- 取消の病室反映: **移動済の取消 → 移動前病室へ戻す**（AC-10。移動元病室の空き枠へ自動割当。空きが無ければ戻さない）。**予定の取消 → 病室は動かさない**（取消履歴のみ）
- 取消状態・戻し反映はモックのためセッション限定（`cancelledMoveIds`・非永続化＝リロードで戻る）。実装は `applyCancelledMoves`（純粋関数）で病棟マップ表示に反映。履歴デモ用に P001（山田 太郎・第2病棟202号室）へ「移動済（203→202）」「予定（202→205）」各1件をサンプル投入
