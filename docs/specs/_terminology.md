ep-10（看護実施／フローシート）／ep-12（看護診断）／ep-13（看護計画）／ep-14（看護評価）の spec・実装で使用する用語の定義集。
参考システム由来の用語と本リポジトリで採用する表記を統一するためのリファレンス。

> このファイルは spec を書く・読む・実装する際の **共通辞書** として使用する。表記揺れがあれば本ファイルに合わせる。

## 看護記録（広義）の構造

「看護記録」は umbrella 用語で、以下の機能群を包含する。

```
看護記録（広義 / umbrella）
  ├─ フローシート          時系列の実施記録（バイタル・食事・ADL・サイン 等）
  ├─ 看護計画              問題点 + 計画 + 評価（ep-12 / ep-13 / ep-14）
  ├─ 看護経過記録          SOAP / 経時記録形式の経過記述（ep-10 us-22, us-23 等）
  └─ 看護サマリ            期間まとめ（週次・月次・退院サマリ 等）
```

| 区分 | 役割 | 関連エピック |
| --- | --- | --- |
| 看護記録（広義） | umbrella。フローシート＋看護計画＋看護経過記録＋看護サマリの総称 | ep-10 全体 |
| フローシート | 時系列のバイタル・実施・観察データ表 | ep-10 us-17, us-18, us-20, us-24, us-25 |
| 看護計画 | NANDA + 問題点 + OTE + 短期目標 + 評価のサイクル | ep-12 / ep-13 / ep-14 |
| 看護経過記録 | SOAP / 経時記録形式の経過記述（カルテ記事相当） | ep-10 us-22, us-23, us-26 |
| 看護サマリ | 期間別のまとめ記事 | （未エピック化、ep-10 拡張範囲） |

### 「看護記録」表記の扱い

本リポジトリのコード・spec には「看護記録」表記が広範囲に存在する。意味で 2 通りある：

1. **広義の看護記録** — フローシート＋看護計画＋看護経過記録＋サマリ をまとめた総称
2. **狭義（= 看護経過記録）** — SOAP／経時記録形式の経過記述のみ

文脈によって意味が変わるので、**狭義を意図する場合は「看護経過記録」と明記する** ルールとする。
新規 spec・新規 UI ラベルは狭義の用法では「看護経過記録」を使用する。

既存コード・既存 spec の「看護記録」表記は、広義であれば残置、狭義であれば 看護経過記録 への統一を順次進める。

### 参考システムマニュアル表記

参考システムマニュアル（`docs/manuals/`）では `看護記録ダイアログ` という名称が使われている。
**マニュアル参照行（spec 冒頭の対応表）はマニュアル表記を尊重し、`看護記録ダイアログ` のまま記載する**。
spec 本文や UI ラベルでは新方針に従い `看護経過記録ダイアログ` 等と呼び替える。

## 看護過程の階層構造

```
看護計画（CarePlan）
  ├─ 長期目標
  ├─ 看護計画明細 = 問題点（ProblemItem）× N
  │   ├─ 領域
  │   ├─ 優先度
  │   ├─ 看護診断（NANDA）
  │   ├─ 問題点（テキスト・本リポジトリ独自）
  │   ├─ 短期目標
  │   └─ 具体策 (OTE)
  └─ 評価（Evaluation）× N（明細単位）
```

## 用語定義

### 看護経過記録（NEW）

SOAP / 経時記録形式で記述する経過記述。狭義の「看護記録」とほぼ同義。  
カルテ記事の一種だが、看護師が看護の観点で書く点で医師記録と区別される。

| 形式 | 内容 |
| --- | --- |
| SOAP | Subjective / Objective / Assessment / Plan（定型文: S/O/A/P の見出し 4 行） |
| 経時記録 | 行頭に時刻（HH:mm）を付けて時系列に記述する形式 |

> 2026-08-24 先方合意により記録形式は SOAP／経時記録の 2 形式に確定（従来案の FOCUS／フリーは廃止）。
> 定型文は 1 つの本文入力欄への挿入テキストとして定義し、構造化入力（SOAP 各欄・経時の時刻＋本文行構造）は
> 現時点では実装スコープ外（将来は多職種の部門診療録全てを対象にした共通の仕組みとして検討余地を残す）。

実装：`src/features/flowsheet/components/NursingRecordDialog.tsx`（型・パス名は `NursingRecord` のまま、UI ラベル・spec 本文は「看護経過記録」を採用）。

### 看護過程

患者の問題抽出 → 計画立案 → 実施 → 評価のサイクル。
**サイドメニュー上の表記は「看護過程」**（旧「看護計画」を 2025 年に変更済）。

### 看護計画（CarePlan）

患者ごとに 1 件以上作成される長期目標と問題点群の集合。
**期間単位** で複数併存可（参考システム仕様）。
**現状モック**: 1 患者 1 計画（`status: 'draft' | 'active' | 'closed'`）。
ep-13 で期間単位への拡張を検討。

| 状態 | 意味 |
| --- | --- |
| draft | 下書き。立案中で未公開 |
| active | 有効。運用中 |
| closed | 終了。退院や計画切替で締めた状態 |

### 長期目標

看護計画全体としての到達目標。退院時に達成されているべき状態を記述する。

### 看護計画明細（ProblemItem） = 問題点

看護計画内の個別の問題点。**「看護計画明細」と「問題点」は同義** で扱う。
UI 上の見出しは「問題点」、データ型は `ProblemItem`。

ProblemItem は以下のフィールドを持つ：

| フィールド | 用語 | 説明 |
| --- | --- | --- |
| `domain` | 領域 | 安全 / 身体 / 精神 / 社会 / 日常生活 / 服薬 / セルフケア |
| `priority` | 優先度 | high / medium / low |
| `nandaCode` | 看護診断（NANDA コード） | 標準診断分類のコード（必須） |
| `problemStatement` | 問題点（本文） | 患者個別の事情を加味した記述（必須・手入力可・本リポジトリ独自） |
| `shortTermGoal` | 短期目標 | 当該問題点の解決に向けた短期的な到達目標 |
| `ote` | 具体策（OTE） | Observation / Therapy / Education の 3 区分 |
| `status` | 状態 | draft / active / evaluating / closed_resolved / closed_cancelled / closed_changed |

### 看護診断（NANDA）

看護診断の標準分類体系。本リポジトリでは NANDA を採用（`NandaDiagnosis` 型）。
コードと診断名を持ち、領域別に分類される。

> **参考システム** の仕様では NANDA 以外の独自分類も想定されているが、本リポジトリでは NANDA で統一。

### 問題点（テキスト）

`ProblemItem.problemStatement` フィールド。**本リポジトリ独自の追加** で、参考システム由来の仕様には存在しない。

NANDA 診断名は標準化された短いラベルだが、看護現場では患者個別の事情を加味した記述が必要なため、自由テキストとして「問題点」を併記する。

例：

| NANDA 診断名 | 問題点（手入力） |
| --- | --- |
| 不眠 | 入眠困難により夜間 2 時間ごとに目覚め、日中の活動性が低下している |
| 服薬管理促進準備状態 | 自己流の服薬調整があり、抗精神病薬の効果が不安定 |

UI 上の表示優先順位：

1. `problemStatement` が設定されている → これを表示
2. `problemStatement` が空 → NANDA 診断名（`nandaMaster[nandaCode].name`）を表示
3. NANDA も解決不可 → コードそのまま表示

### 短期目標 / 長期目標

| 用語 | 範囲 | 主体 |
| --- | --- | --- |
| 長期目標 | 看護計画全体（退院時など） | CarePlan |
| 短期目標 | 各問題点の解決 | ProblemItem |

### 具体策（OTE）

問題点に対する具体的な看護介入。3 区分。

| 区分 | 略号 | 内容 |
| --- | --- | --- |
| 観察 | O (Observation) | 症状・状態・行動の観察 |
| 援助 | T (Therapy) | 看護師による直接援助・支援 |
| 指導 | E (Education) | 患者・家族への指導 |

### 看護評価（Evaluation）

問題点単位で実施する評価。達成度（`achievement`）と所見（`findings`）と次のステータスを持つ。

| achievement | 意味 |
| --- | --- |
| not_achieved | 未達成 |
| partial | 一部達成 |
| achieved | 達成 |

評価結果に応じて問題点のステータスを遷移：

- 達成 → closed_resolved（解決でクローズ）
- 中止 → closed_cancelled
- 計画変更 → closed_changed
- 継続 → active（または evaluating）

### 看護過程の日付概念

時刻・日付の概念は混同しやすいため厳密に区別する。看護過程クラスタ（ep-12/13/14）で扱う日付は以下：

| 用語 | フィールド | 対象 | 意味 |
| --- | --- | --- | --- |
| **作成日** / **立案日** | `CarePlan.createdAt` / `ProblemItem.createdAt` | 計画 / 問題点 | レコードを作成した日（= 立案日） |
| **適用日** | `ProblemItem.createdAt` で代用 | 問題点 | 看護診断を看護計画明細として適用した日。本リポジトリでは createdAt と区別しない |
| **診断日** | `ProblemItem.diagnosedAt` | 問題点 | 看護診断として最終確定した日。立案直後 = 診断日となるケースが多いが、運用上区別したい場合に別管理する（mock 改修フェーズ 1 で追加） |
| **更新日** | （changeLogs 時系列）| 計画 / 問題点 / 評価 | 直近の変更日。changeLogs から導出 |
| **期間開始日** | `CarePlan.periodStart` | 計画 | 当該計画の期間開始日（mock 改修フェーズ 2 で追加） |
| **期間終了日** | `CarePlan.periodEnd?` | 計画 | 当該計画の期間終了日。継続中なら未設定（mock 改修フェーズ 2 で追加） |
| **最終評価日** | `ProblemItem.lastEvaluatedAt` | 問題点 | 直近の評価実施日 |
| **次回評価期限** | `ProblemItem.nextEvaluationDueAt` | 問題点 | 次回評価が必要な日（lastEvaluatedAt + 1 ヶ月で自動計算） |
| **クローズ日** | `ProblemItem.closedAt` | 問題点 | 計画明細をクローズした日 |
| **評価日** | `Evaluation.evaluatedAt` | 評価 | 当該評価レコードの実施日 |

#### よくある混同ポイント

| 混同しやすいペア | 区別ポイント |
| --- | --- |
| 立案日 vs 診断日 | 立案日 = 計画明細生成日 / 診断日 = 看護診断として確定した日。多くは同日だが、別管理可 |
| 立案日 vs 適用日 | 概念上同じ（参考システム由来の用語）。本リポジトリでは createdAt 1 つで運用 |
| 最終評価日 vs 評価日 | 最終評価日 = 問題点側に持つ最新評価日 / 評価日 = 評価レコード自体の日付 |
| 期間開始日 vs 立案日 | 期間開始日 = 計画期間の起点 / 立案日 = レコード作成日。多くは同日 |

### 看護診断ダイアログ機能タブ

ep-12 で設計する看護診断ダイアログのタブ構成：

| タブ | 用途 |

チェック・編集・削除・追加 のいずれかの操作で **候補化** される。
適用 / 診断確定で看護計画明細として確定する。

## 状態色の使い分け

「状態色」という語は 2 つの別概念に使われてきた。**混同を避けるため呼称・表示形状・色の作り方の 3 点で区別する**（2026-08-25 確定）。

| | **患者状態色** | **観察状態色** |
| --- | --- | --- |
| 何の色か | Dr 観察ステータス（患者の様態） | 隔離拘束観察で選んだ観察状態 |
| 値 | 安定／観察中／不安定／重症 の **4 値固定**（ver0.35 で純化） | 隔離拘束状態マスタで**現場が増減できる**（未記入・浅眠・落ち着き・不穏・睡眠・中途覚醒 等） |
| 単位 | **患者 1 人につき 1 つ**（現在の様態） | **観察 1 コマにつき 1 つ**（時間枠ごとの記録） |
| 表示形状 | **ドット付きチップ**（点） | **グリッドセルの塗り**（面） |
| 色の作り方 | 重症度グラデーションの**鮮やかなベタ色**（緑→橙→赤。例: 安定 `#22c55e`） | **淡い背景色＋濃い文字色のペア**（例: 落ち着き 文字 `#166534` / 背景 `#dcfce7`） |
| 出る場所 | 病棟マップ、患者検索一覧 | フローシート隔離拘束タブの観察グリッド、隔離拘束一覧 |
| 実装 | `STATUS_CONFIG`（`src/data/mockData.ts`）／`StatusBadge.tsx` | `MASTER_OBSERVATION_STATES`（同上・型 `ObservationStateConfig`） |
| エピック | ep-01（病床マップ）、ep-09（患者一覧） | ep-07（観察記録） |

### 運用ルール

1. **呼称を分ける**: spec 本文・UI 文言では「状態色」と単独で書かず、必ず **「患者状態色」** か **「観察状態色」** と書く。
2. **形状で分ける**: 患者状態色は点（チップ）、観察状態色は面（セル塗り）。色覚に依存せず判別できるようにするため、この対応は入れ替えない。
3. **色の作り方で分ける**: 同じ色相帯（緑・橙・赤）が両者に現れても、**ベタ塗り＝患者状態色／淡背景＋濃文字＝観察状態色**という濃度差で区別できる状態を保つ。観察状態をマスタに追加するときも「淡背景＋濃文字」のペアで登録する。
4. **混ぜない**: 一方の色をもう一方の意味に流用しない。片方のマスタ色をもう片方の画面で参照しない（`STATUS_CONFIG` と `MASTER_OBSERVATION_STATES` は相互に import しない）。

> **記録サマリー帯（ep-10 us-17）の色は上記いずれとも別物**。「いつ・どの記録が・どの程度あるか」を示す**記録種別の色**で、患者状態でも観察状態でもない。単一ソースは `src/components/karte/recordCategoryColors.ts`（診療録タブと共有）＋ `src/components/flowsheet/recordBadgeMaster.ts`（部門色）。
>
> なお **部門記録簿（us-22）に患者状態色は置かない**（旧 AC-8 は 2026-08-25 に削除）。
