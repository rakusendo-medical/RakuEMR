## ユーザーストーリー

- **As a** 受け持ち看護師
- **I want** 看護診断ダイアログで検索・セット・履歴から診断候補を選定し、項目編集を経て診断を確定したい
- **So that** 看護計画の根拠となる診断情報を明示し、計画明細生成までを一連で完了できる

## 画面要素（要素ツリー）

```
- 看護計画画面 (/care-plan/patients/:patientId) [ep-13]
  - [看護診断より追加] ボタン: 看護診断ダイアログを開く
- 看護診断ダイアログ
  - ヘッダー
    - 患者基本情報サマリ
    - 前回診断候補選択情報: 「前回: YYYY/MM/DD HH:mm 操作者名」（履歴あり時のみ）
  - 機能タブ
    - 検索タブ
      - キーワード入力（複数 AND 条件、空文字で全件）
      - [検索] / クリア
      - 候補のみ表示チェック
      - [診断候補のクリア]
    - セットタブ
      - 看護診断セットセレクト（マスタから選択）
      - 候補のみ表示チェック
      - [診断候補のクリア]
    - 履歴タブ
      - 過去登録診断リスト（時系列降順）
      - 行クリックで詳細欄に表示、編集可
  - 問題点テキスト欄（タブ下部に常設・本リポジトリ独自）
    - 領域・診断名選択とは独立した自由テキスト入力欄（必須）
    - NANDA 選択時は診断名で自動補完されるが、ユーザーは自由編集可
    - 患者個別の事情を加味した問題点記述を保持（例: 「[NANDA] により夜間 2 時間ごとに目覚める」）
    - 最大 500 文字、空欄では確定不可
  - 診断閲覧領域（タブ共通）
    - 領域グループ（安全 / 身体 / 精神 / ... など領域マスタ）
    - 各領域内: 診断リスト
      - 選択アイコン: 未選択（白抜き）/ 候補（色変） クリックで候補化トグル
      - 診断コード + 診断名
      - 項目件数表示（候補化済の場合）
  - 診断詳細内容編集領域（選択中の診断、画面右側 or 下部）
    - 大分類（カテゴリグループ）
      - 小分類（サブカテゴリ）
        - 項目（具体的な記述）
          - 項目アクションアイコン: 編集 / 削除 / 確定 / 中止
          - 編集モード時はテキストエリア化
      - [新規] 項目追加ボタン
  - フッターアクション
    - 適用日入力（初期: 操作日）
    - [適用] ボタン: 選択候補診断から看護計画明細を生成して親（[ep-13]）に連携
    - [診断] ボタン: 候補から最終診断を選定（診断日入力ダイアログ）
    - [候補のみ表示] チェック
    - [診断候補のクリア]
    - [クリア] ボタン: 候補内容を破棄、マスタから再取得
    - [閉じる] ボタン: 候補を保存して閉じる
    - × ボタン / Esc / 背景クリック: 操作内容は破棄して閉じる
- 診断登録ダイアログ（[診断] クリック時）
  - 確定する診断選択
  - 診断日入力（必須）
  - [診断] / [キャンセル]
```

## 振る舞い

- **[看護診断より追加] クリック**: 看護診断ダイアログを開く（検索タブ初期表示）
- **検索タブ キーワード入力**: AND 条件で診断指標を絞り込み、空文字で全件表示
- **セットタブ セレクト変更**: 当該セットに紐づく診断を一覧表示
- **セット「候補のみ表示」チェック**: 候補化された診断のみフィルタ
- **履歴タブ 過去診断選択**: 詳細欄に当該診断の項目を表示。編集・追加・削除可能
- **履歴タブ [更新]**: 過去診断の内容変更を確定（変更日時・操作者を履歴に追加）
- **問題点テキスト欄の自動補完**: NANDA を選択すると診断名で自動補完される。空欄もしくは未編集の場合のみ補完、ユーザーが手で編集した内容は上書きしない
- **問題点テキスト欄の編集**: NANDA 選択後でも自由に編集可能。患者個別の表現で書き換えできる
- **空欄では確定不可**: NANDA 選択 + 問題点テキスト両方が必須。どちらか欠けると [選択] ボタンが disabled
- **診断行の選択アイコンクリック**: 候補化トグル
- **診断行のチェックボックス選択 / 項目編集 / 項目削除 / 項目追加 のいずれか操作**: 当該診断が候補化される（選択アイコンが色変、項目件数が表示される）
- **診断詳細 編集アイコン**: 当該項目をテキストエリア化
- **診断詳細 削除アイコン**: 項目削除
- **診断詳細 確定アイコン**: テキストエリア編集を確定（テキスト→項目）
- **診断詳細 中止アイコン**: 編集内容破棄
- **診断詳細 [新規]**: 項目追加（新規入力モード）
- **適用日入力 + [適用]**: 候補診断から看護計画明細を生成して親 [ep-13] に渡す。ダイアログは閉じる
- **[診断]**: 診断登録ダイアログを開き、確定する診断選択 + 診断日入力で最終確定
- **[診断候補のクリア]**: 全候補をクリア（確認なし or 確認 1段階）
- **[クリア]**: 編集中の候補内容を破棄してマスタから再取得
- **[閉じる]**: 候補を保存して閉じる
- **× / Esc / 背景クリック**: 操作内容を破棄して閉じる
- **マスタから削除された候補診断**: 一覧の最後に削除診断名が追加表示される（最新情報を見るには [診断候補のクリア]）

## 受け入れ基準（AC）

- [ ] **AC-1: 看護診断ダイアログを開ける**
  - **Given** 看護計画画面の問題点タブを表示している
  - **When** [看護診断より追加] をクリックする
  - **Then** 看護診断ダイアログが開かれ、検索／セット／履歴タブと診断閲覧・詳細編集領域が表示される

- [ ] **AC-2: 検索タブで診断指標から絞り込める**
  - **Given** 看護診断ダイアログの検索タブを開いている
  - **When** キーワードを入力する（複数AND条件可）、または空文字のままにする
  - **Then** 検索結果に該当する診断、または全診断が表示される

- [ ] **AC-3: セットタブで看護診断セットから選択できる**
  - **Given** 看護診断ダイアログのセットタブを開いている
  - **When** セットコンボボックスから看護診断セットを選択する
  - **Then** セットに紐づく診断情報が一覧表示される。「候補のみ表示」でさらに候補診断のみ抽出可能

- [ ] **AC-4: 履歴タブで過去診断を参照・編集できる**
  - **Given** 履歴タブを開いている
  - **When** 過去登録した診断を選択する
  - **Then** 当該診断の詳細欄が表示され、内容編集・削除・新規追加が可能。[更新] で履歴が変更される

- [ ] **AC-5: 診断候補を選定できる**
  - **Given** 検索タブまたはセットタブで診断を表示している
  - **When** チェックボックス選択／項目編集／項目削除／項目追加 のいずれかを行う
  - **Then** 当該診断が候補化される。診断名前のアイコンが選択アイコンに変わり、選択項目件数が表示される

- [ ] **AC-6: 候補確定の閉じ操作が区別される**
  - **Given** 候補を選定している
  - **When** [閉じる] ボタンをクリックする、または別の閉じ方（× ボタン等）を行う
  - **Then** [閉じる]: 候補が確定保存される。別の閉じ方: 操作内容は破棄される

- [ ] **AC-7: 診断詳細の項目を編集・追加・削除できる**
  - **Given** 診断閲覧で診断を選択して詳細を表示している
  - **When** 編集アイコンをクリックして項目をテキストエリアに変更し、確定アイコンで保存する／削除アイコンで項目削除／[新規] で項目追加する
  - **Then** 大分類・小分類・項目の各レベルで内容が反映される

- [ ] **AC-8: 看護診断を確定できる（適用）**
  - **Given** 候補診断と詳細内容を整えている
  - **When** 適用日を入力して [適用] ボタンをクリックする
  - **Then** 看護計画画面に看護診断が反映され、看護計画明細として連携される

- [ ] **AC-9: 診断登録（最終確定）操作**
  - **Given** 候補から最終診断を選定している
  - **When** 確定する診断名を選択し、診断日を入力して [診断] をクリックする
  - **Then** 当該診断が最終診断として確定される

- [ ] **AC-10: 診断候補のクリアが可能**
  - **Given** 候補が複数選定されている
  - **When** [診断候補のクリア] をクリックする
  - **Then** 全ての候補がクリアされる

- [ ] **AC-11: 前回診断候補選択情報が表示される**
  - **Given** 前回看護診断時に候補選択を行っている
  - **When** ダイアログを開く
  - **Then** 前回候補選択を行った日時と操作者が表示される

- [ ] **AC-12: 問題点テキストを手入力で記述できる**
  - **Given** 看護診断ダイアログを開き NANDA を選択している
  - **When** ダイアログ下部の「問題点（手入力可・必須）」テキスト欄に患者個別の問題点記述を入力する
  - **Then** 当該テキストが ProblemItem.problemStatement に保存され、看護計画明細の主見出しとして表示される

- [ ] **AC-13: NANDA + 問題点 両方が必須**
  - **Given** 看護診断ダイアログを開いている
  - **When** NANDA 未選択 または 問題点テキスト空欄の状態
  - **Then** [選択] ボタンが disabled となり確定できない

## 状態遷移 / バリデーション

- 候補化トリガー: チェックボックス選択／項目編集／項目削除／項目追加 のいずれか
- 候補状態: ダイアログ内のローカル状態。[閉じる] で永続化、× で破棄
- マスタ削除診断の取扱: 候補に残っている場合は一覧末尾に削除済表示で残す（参照のみ）

## 補足

- 診断ラベル体系（NANDA 等）の採用可否は別途検討。本 spec は領域 → 大分類 → 小分類 → 項目 の汎用階層として記述
- 診断項目の表示有無は看護診断マスタで設定（診断名横の項目表示等）
- 既存実装（`NandaSelectDialog.tsx`）の延長ではなく、新規 `NursingDiagnosisDialog.tsx` として作り直す想定
- 適用日と診断日は別概念:
  - 適用日: 看護計画明細を生成する日付
  - 診断日: 最終診断として記録する日付

### 問題点テキスト追加に伴うデータモデル影響（要 ep-13 連携）

参考システム由来の仕様にはない、本リポジトリ独自の追加機能。NANDA 標準分類だけでは表現しきれない患者個別の問題点を併記できるようにする。

- `ProblemItem.problemStatement?: string` を新設（**問題点テキスト**を保持、新規/編集時は必須・既存データは未設定でも可）
- `ProblemItem.nandaCode: string` は **必須のまま維持**（標準分類は引き続き必須）
- 表示時は `problemStatement` があればこれを優先、なければ NANDA マスタ名にフォールバック
- 看護計画明細としての扱いは標準（領域・優先度・OTE・短期目標は同じ構造）

ep-13 看護計画 spec 側でも本変更を反映する必要あり（[ep-13/us-29 ProblemItem 表示](../ep-13-care-plan/us-29-care-plan.spec.md)）。

### 用語整合

詳細は [docs/specs/_terminology.md](../_terminology.md) 参照。要点：

- **問題点（テキスト）** = `ProblemItem.problemStatement`、本リポジトリ独自フィールド
- **看護診断（NANDA）** = `ProblemItem.nandaCode` + マスタ参照
- 両者は併存するが、UI 上の主見出しは **問題点（テキスト）** が優先表示される
