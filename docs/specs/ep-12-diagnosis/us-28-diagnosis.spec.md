## ユーザーストーリー

- **As a** 受け持ち看護師
- **I want** NANDA 診断を選択し患者個別の問題点（手入力可）と組み合わせて看護計画明細を作成したい
- **So that** 標準分類に基づきつつ患者個別事情を加味した看護計画を立案できる

## 画面要素（要素ツリー）

```
- 看護計画画面（[ep-13]）
  - [看護計画を追加] / [編集] ボタン → 看護計画明細編集ダイアログ
    - サブダイアログとして看護診断ダイアログを起動

- 看護診断ダイアログ（NandaSelectDialog）
  - ヘッダー: タイトル「NANDA 看護診断を選択」
  - フィルタ部
    - キーワード入力（name / code 単一クエリ、空文字で全件）
    - 領域フィルタセレクト
      - 値: すべて / 安全 / 身体 / 精神 / 社会 / 日常生活 / 服薬 / セルフケア
  - 診断リスト（ラジオ選択）
    - 「よく使う診断」セクション（NandaDiagnosis.frequentlyUsed=true のみ、フィルタ後に該当があれば表示）
    - 「すべての診断」セクション（残り全件、フィルタ後）
    - 各行: ラジオ + 診断コード + 診断名 + 領域表示
    - 該当なしテキスト: 「該当する診断がありません」
  - 問題点テキスト欄（必須・手入力可）
    - 自由テキスト（multiline、最大 500 文字）
    - NANDA 選択時に診断名で自動補完（ユーザー編集後は上書きしない）
    - 患者個別事情を加味した問題点を記述
  - フッター
    - [キャンセル] = 破棄して閉じる
    - [選択] = NANDA + 問題点テキストを返却（NANDA 選択 + 問題点空でない 両方必須）

- 履歴参照モード（看護診断ダイアログのもう 1 つの起動経路）
  - 過去登録した看護診断を時系列で参照
  - ヘッダー: 患者基本情報サマリ + 件数 + 現在表示インデックス
  - ナビゲーション: [前へ] [次へ] ボタンと「N / M 件」表示
  - 編集不可: 内容は読み取り専用で表示
  - 表示項目: 領域 / コード / 名称 / 問題点テキスト / 立案日 / 診断日 / 立案者
  - フッター: [閉じる]
```

## 振る舞い

- **看護診断ダイアログを開く**: 看護計画明細編集ダイアログの「NANDA 選択...」ボタンから起動。検索タブの相当（フィルタ + リスト）を初期表示
- **キーワード入力**: name / code を含む診断を絞り込み（空で全件）
- **領域フィルタ変更**: 当該領域のみ表示
- **NANDA 行のラジオクリック**: 選択中とし、問題点テキストが空 or 未編集なら診断名で自動補完
- **問題点テキスト入力**: 必須。NANDA 選択後でも自由編集可
- **[選択] クリック**: 検証通過時 onSelect(code, problemStatement) を呼び出してダイアログを閉じる
- **[キャンセル] / × クリック**: 入力内容を破棄して閉じる
- **履歴参照モード起動**: 看護過程画面に「過去診断を参照」リンクを設置（mock 改修フェーズ 1 で対応）。クリックで履歴参照モードのダイアログを開く
- **[前へ] / [次へ]**: 過去診断の前後の登録に切替

## 受け入れ基準（AC）

- [ ] **AC-1: 看護診断ダイアログを起動できる**
  - **Given** 看護計画明細編集ダイアログを開いている
  - **When** 「NANDA 選択...」ボタンをクリックする
  - **Then** 看護診断ダイアログが起動し、診断リストが表示される

- [ ] **AC-2: キーワードで絞り込める**
  - **Given** 看護診断ダイアログを表示している
  - **When** キーワード（name / code 部分一致）を入力する
  - **Then** 該当する診断のみが表示される（空文字で全件）

- [ ] **AC-3: 領域でフィルタできる**
  - **Given** 看護診断ダイアログを表示している
  - **When** 領域フィルタを変更する
  - **Then** 当該領域に属する診断のみが表示される。「すべて」で全件

- [ ] **AC-4: よく使う診断が分けて表示される**
  - **Given** 看護診断ダイアログを表示している
  - **When** フィルタ後の診断にて NandaDiagnosis.frequentlyUsed=true が含まれる
  - **Then** 「よく使う診断」セクションが先頭に表示され、残りは「すべての診断」セクションに表示される

- [ ] **AC-5: NANDA 選択 + 問題点 両方必須で確定できる**
  - **Given** 看護診断ダイアログを表示している
  - **When** NANDA 行のラジオを選択し、問題点テキストを入力した状態で [選択] をクリックする
  - **Then** onSelect(code, problemStatement) が呼ばれてダイアログが閉じる

- [ ] **AC-6: 入力欠如時は確定不可**
  - **Given** 看護診断ダイアログを表示している
  - **When** NANDA 未選択 または 問題点空欄 の状態
  - **Then** [選択] ボタンが disabled となる

- [ ] **AC-7: NANDA 選択時に問題点が自動補完される**
  - **Given** 問題点テキストが空 または ユーザーが編集していない状態
  - **When** NANDA 行を選択する
  - **Then** 問題点テキストに当該診断名が自動入力される

- [ ] **AC-8: ユーザー編集後の問題点は上書きされない**
  - **Given** 問題点テキストをユーザーが編集している
  - **When** 別の NANDA 行に選択を変える
  - **Then** 問題点テキストは変更されない（編集内容を尊重）

- [ ] **AC-9: 過去診断を履歴モードで参照できる**
  - **Given** 看護過程画面を表示している
  - **When** 「過去診断を参照」リンクをクリックする
  - **Then** 看護診断ダイアログが履歴参照モードで起動し、当該患者の過去診断が時系列で 1 件ずつ表示される。前へ／次へボタンでページめくりできる。編集はできない

## 状態遷移 / バリデーション

- ダイアログモード: 通常モード（編集可）/ 履歴参照モード（読み取り専用）の 2 種
- 通常モード [選択] ボタン disabled 条件: NANDA 未選択 OR 問題点 trim 空
- 問題点テキスト最大: 500 文字
- 履歴参照モードのデータソース: ProblemItem の作成履歴（changeLogs）または ProblemItem 自体の時系列。本リポジトリ初版では「該当患者の全 ProblemItem を createdAt 昇順で並べ、診断名 + 問題点 + 領域 + 立案日 + 診断日を表示」する。

## 補足

### 既存実装の状況

- `src/features/carePlan/components/NandaSelectDialog.tsx` に **本 spec の通常モード** が概ね実装済（キーワード / 領域 / よく使う / 問題点テキスト / NANDA + 問題点 必須）

### 削除した参考システム機能（理由は changes/ep-12-13-14-integration.md 参照）

- 看護診断セット（マスタ）— マスタ管理機能は別途 EP/US で起草
- 候補プール（候補化トグル） — 1 ダイアログ = 1 診断追加で運用
- 大分類 / 小分類 / 項目の階層編集 — マスタ側の問題、別途データ構造設計
- 適用 / 診断確定の 2 段階フロー — 即時反映で十分
