### 経緯

KartePage の `orders` タブは段階 1 でプレースホルダ。本 us で **既存 ORDERS データを患者別フィルタで一覧表示** する最小実装に置き換える。本格的な指示作成・編集は別エピック（オーダ管理本実装）扱い。

## ユーザーストーリー

- **As a** 主治医・看護師
- **I want** カルテ画面の「指示簿」タブで、その患者のオーダ（処方・注射・検査・画像・心理検査・ECT・リハビリ・入院定時・IF・テキスト）を **定期／臨時／IF／文字** にグルーピングして一覧し、**臨時オーダは行をクリックして内容（用量/用法コメント・日数・予定日・備考）を確認・変更**したい
- **So that** カルテを離れず実施中・予定のオーダを把握でき、臨時オーダの微修正もその場で行え、指示状況タブ（us-51）への動線で管理画面に飛べる

## 画面要素（要素ツリー）

```text
- OrdersTab（mode 別配色 SectionHeader）
  - フィルタ Chip 行（グループ）: 全て / 定期 / 臨時 / IF / 文字
  - ステータス Chip 行: 全て / 指示済 / 実施中 / 予定 / 中止 / 実施済
  - オーダ一覧（テーブル風 or カード風・dense）:
    - 行ごとに: type Chip / 内容 / スケジュール / ステータス Chip / 期間（startDate + days） / 担当医
    - **臨時グループの行はクリック可**（カーソル pointer・title「クリックで内容を確認・変更」）→ 臨時オーダ編集ダイアログ
  - 件数表示: 「X 件」
  - 上部右: 「指示状況タブを開く」ボタン（commitTab で 'order-status' へ）
- 臨時オーダ編集ダイアログ (OrderEditDialog・臨時行クリックで開く):
  - 見出し: 共通 `OrderDialogTitle`「{種別}オーダ（編集）　対象患者: {患者番号}　{氏名}」（濃紺バー）
  - 処方・注射（処方系）: 「作成中のオーダ」と同じ 2 行表示（Rp番号/名称/用量 ＋ 用法/日数）で、**用量コメント・用法コメント（行ごと）・日数（注射は回数）** を編集
  - 検査・画像・心理検査・ECT（非処方系）: 内容は表示のみ
  - 全種別共通: **予定日（date）・備考** を編集
  - フッター: キャンセル／保存
```

## 振る舞い

- **タブ初期表示**: その患者の ORDERS 全件を新しい順で表示
- **グループフィルタ**: クリックで該当グループ（定期／臨時／IF／文字）のみ。OrderType→グループの対応は「定期＝入院定時・リハビリ／臨時＝処方・注射・検査・画像・心理検査・ECT／IF＝IF／文字＝テキスト」
- **status フィルタ**: クリックで該当ステータスのみ
- **グループ + status は AND 条件**
- **臨時オーダ行クリック → 編集ダイアログ**: 種別「臨時」の行をクリックすると OrderEditDialog が開く。処方系は content を構造化データ（Rp 行）へ復元して 2 行表示で編集、非処方系は内容表示のみ。用量/用法コメント・日数・予定日・備考を変更できる。
- **保存 → オーバーレイ反映**: 保存すると `orderOverrides`（オーダ id → 変更内容）に書き込み、一覧表示に上書き適用される（seed `ORDERS` / `dynamicOrders` は破壊しない）。処方系は編集後の Rp 行から content・日数を再構築する。**モックのためセッション限定・非永続**（リロードで初期化）。

## 受け入れ基準（AC）

- [ ] **AC-1: 患者別オーダ一覧表示**: `ORDERS.filter(o => o.patientId === patient.id)` で抽出
- [ ] **AC-2: グループフィルタ Chip**: 5 種（全て + 定期 / 臨時 / IF / 文字）
- [ ] **AC-3: status フィルタ Chip**: 6 種（全て + 5 OrderStatus）
- [ ] **AC-4: テーブル / カード行表示**: type Chip / 内容 / スケジュール / ステータス Chip / 期間 / 担当医
- [ ] **AC-5: 「指示状況タブを開く」ボタン**: クリックで `commitTab('order-status')`（us-33 AC-10 ハッシュ仕様準拠）
- [ ] **AC-6: 件数表示**
- [ ] **AC-7: 0 件時の空状態表示**
- [ ] **AC-8: design-rules §3 / §6 / §12 準拠**
- [ ] **AC-9: 臨時オーダの確認・変更**:
  - **Given** 指示簿タブで種別「臨時」の処方オーダ行を表示している
  - **When** 行をクリックし、用量コメント・用法コメント・日数・予定日・備考を変更して [保存] する
  - **Then** OrderEditDialog が開き（作成中のオーダと同じ 2 行表示）、保存後は一覧の内容・期間・予定日にオーバーレイが反映される（非処方系の臨時オーダは予定日・備考のみ編集可）

## 補足

- **オーダ種別のグルーピング**（指示簿タブは種別を定期／臨時／IF／文字にグルーピングして表示・フィルタする。内部の `OrderType` はそのまま保持）:
  - **定期**: 入院定時（入院専用の定時処方）・リハビリ（治療形態）
  - **臨時**: 処方・注射・検査・画像・心理検査・ECT
  - **IF**: IF ／ **文字**: テキスト
  - 旧「定時処方」は廃止し「入院定時」へ統合済み（ver0.27 で整理）。`OrderType` は計 10 種（処方／注射／検査／画像／心理検査／ECT／リハビリ／入院定時／IF／文字）。フローシート [us-17] の 1 文字種名「薬」は処方・入院定時の両方に対応する
- データソース: 既存 `mockData.ts` の `ORDERS`（＋オーダ入力で追加された `dynamicOrders`）。新規データ追加なし
- **臨時オーダ編集の実装**（ep-11 オーダ入力の後に追加）:
  - `OrderEditDialog.tsx`（新規）: 臨時オーダの確認・変更ダイアログ。作成中のオーダ（[ep-11 us-55]）と同じ 2 行表示・編集 UI を流用
  - `useAppStore.ts`: `orderOverrides: Record<orderId, OrderOverride>` ＋ `setOrderOverride`（**非永続**・partialize から除外）。表示時に seed/dynamic へ上書き適用
  - `prescriptionContent.ts`: content→構造化データ復元の共有関数 `orderToDrugs`／`orderToPendingRx`（オーダ送信画面の作成中復元と共用。用量/用法コメント・日数も content から復元）
  - 既知の制約: 一包化指定の無い処方を編集保存すると content に「（包1）」が付く場合がある（`orderToPendingRx` が既定で一包化=1 とするため。DO 機能と同じ既存挙動）
- 共有ファイル変更:
  - `KartePage.tsx`: `KarteTabContent` の `orders` 分岐に `<OrdersTab patient={patient} mode={mode} onOpenOrderStatusTab={...} />` を埋込（meta プレースホルダから移動）
  - `OrdersTab.tsx`: 新規（＋臨時行クリックで OrderEditDialog 起動）
  - `types/index.ts` / `mockData.ts` の `MASTER_*`: 触らず
- 段階 2 の基本は **一覧表示**。臨時オーダに限り、上記のとおり内容（コメント・日数・予定日・備考）の**限定的な変更**をオーバーレイで許可する。オーダの新規作成はオーダ送信画面（[ep-11]）で行う
- 看護用オーダ（一括バイタル等）の扱いは us-49 サイドバー拡張で別途対応
