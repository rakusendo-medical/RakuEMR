## ユーザーストーリー

- **As a** 病棟看護師・主治医
- **I want** 入院患者のカルテ画面の「看護過程」タブから、看護診断・看護計画・看護評価の各画面に直接アクセスしたい
- **So that** カルテ画面を離脱せずに看護過程業務（診断 → 計画 → 評価のサイクル）を完結できる

- [ ] **前提-2**: ep-13（看護計画・期間複数計画モデル）の `mock 改修フェーズ 2` が完了している
- [ ] **前提-3**: ep-14（看護評価）の `mock 改修フェーズ 2` が完了している
- [ ] **前提-4**: ep-12〜14 の主要コンポーネント（`PatientCarePlan` / 看護診断画面 / 評価画面）に **`embedded` / `patientId` prop** が用意されている、または `KarteAlphaPage` の埋込パターンを参考に統合可能なシグネチャが揃っている
- [ ] **前提-5**: PM が「看護過程タブの構造（タブ内タブ vs 単一画面）」について方針確定

前提が揃わないうちは着手しない。**MASTER は ep-12〜14 担当ワーカー（要 PM ヒアリング）から進捗を確認し、本 us 着手のタイミングを判定する**。

## 画面要素（要素ツリー・暫定）

```
- KartePage (/karte/:patientId)
  - メインタブ: 看護過程タブ  (mode='inpatient' で活性、mode='outpatient' で disabled)
    - 看護過程タブの中身（暫定構造）:
      - サブタブ or 連動エリア:
        - 看護診断 (ep-12: PatientCarePlan / NursingDiagnosis)  ← 既存実装を埋込
        - 看護計画 (ep-13: 看護計画モデル)                      ← 既存実装を埋込
        - 看護評価 (ep-14: 評価項目立案・定期評価)               ← 既存実装を埋込
      または:
        - 統合タイムライン: 診断 → 計画 → 評価 を時系列で表示
```

**構造の最終確定は前提-5（PM 方針確定）後**。本 spec では暫定として **3 サブタブ**（診断／計画／評価）方式を仮置きする。

## 振る舞い（暫定）

- **看護過程タブクリック（mode='inpatient'）**: 看護過程タブが開き、3 サブタブ（または PM 確定後の構造）が表示
- **サブタブ切替**: 各 ep の既存実装が埋込で表示される
- **mode='outpatient'**: 看護過程タブは disabled（段階 1 で確立済仕様）
