# RakuEMR デザインルール

UI/UX の振る舞いと配置を **言語化** したリファレンス。視覚要素（カラー / タイポ / コンポーネント）は [`/design-guide`](src/components/designGuide/DesignGuide.tsx) を SoT とし、本ドキュメントは **振る舞い・配置・状態** のルールを担当する。

> 適用範囲：本リポジトリの新規画面実装、外来 EMR 刷新プロジェクト、マスタ管理画面など。
> 既存画面は刷新時に順次本ルールに揃える。

---

## 0. 基本原則

| # | 原則 | 補足 |
| --- | --- | --- |
| P1 | 同じ操作は同じ場所・同じ見た目 | 一貫性 > 個別最適化 |
| P2 | 破壊的アクションは必ず確認を経る | 取消し可能な場合でも警告は出す |
| P3 | 進捗・状態を常に可視化 | 操作の結果が見えること（snackbar / 状態 chip / 空状態） |
| P4 | キーボード操作で完結できる | フォーム / ダイアログは Tab / Enter / Esc で操作可能 |
| P5 | 未保存の変更は失わせない | 離脱時に確認ダイアログ |
| P6 | 表記揺れを作らない | 用語は [docs/specs/_terminology.md](specs/_terminology.md) に集約 |

## 1. レイアウト

### 1.1 画面の最大幅
- `Container maxWidth="xl"` (1536px) を基本、表組み中心は `xl` + `disableGutters`
- 詳細画面の単一カラムは `maxWidth="md"` (900px) 程度

### 1.2 主要 3 領域

```
┌─ AppBar / 患者ヘッダー（任意）──────────────┐
├─ サイドバー ──┬─ メインコンテンツ ─────────┤
│ (220 / 60px) │ ヘッダー: 操作バー         │
│             │ ボディ: メインビュー       │
│             │ フッター: ページング/集計  │
└──────────────┴──────────────────────────────┘
```

### 1.3 セクション構造
- 大セクション = `Paper variant="outlined"` + `SectionHeader`（折りたたみ可能）
- 中セクション = `Box` + `Typography variant="subtitle2"` + `Divider`
- セクション間スペース = `mb: 1.5` ～ `mb: 2`

## 2. ナビゲーション

### 2.1 戻るボタン

| 配置 | 振る舞い |
| --- | --- |
| **左上** | 直前画面に戻る（履歴で 1 段戻る）。アイコン `ArrowBack` + ラベル「戻る」 |
| 例外: カルテ画面 | タブバー左端に「一覧に戻る」（既存 KarteAlphaPage パターン）。ダーク背景で視認性確保 |

未保存変更がある場合: `window.confirm` ではなく **MUI Dialog** で「保存せずに戻る / キャンセル / 保存して戻る」の 3 択を提示。

### 2.2 パンくず
- ヘッダー右部に `Breadcrumbs` を表示する場合は `>` 区切り、最終セグメントは太字
- 階層 3 段以上で導入を検討。2 段以下は省略可

### 2.3 タブ
- 同じデータコンテキスト内の表示切替に使用（例：入院/退院手続きタブ）
- 異なる業務単位はタブではなくサイドバーで切替
- タブバーの下に必ず `borderBottom` を付けて領域を明示

## 3. ボタン

### 3.1 階層と配置

| 階層 | variant | 用途 | 配置 |
| --- | --- | --- | --- |
| **Primary** | `contained` color=`primary` | 主要アクション（保存・確定・新規作成） | **右端** |
| **Secondary** | `outlined` color=`primary` | 補助アクション（編集・参照） | Primary の左 |
| **Tertiary** | `text` | 軽量アクション（リセット・展開） | Secondary の左 |
| **Destructive** | `contained` color=`error` または `outlined` color=`error` | 削除・中止 | **明示的に分離**（左端 or 別グループ） |
| **Cancel** | `text` または `outlined` | 戻る・キャンセル | **左端** |

### 3.2 配置パターン

#### ダイアログのフッター
```
[キャンセル] ........................................ [更新] [Primary]
                  ←余白で分離→
```
- 左側: 取消し系（[キャンセル]）
- 右側: 確定系（[Primary]）
- 中間（編集モード時）: 編集系・破壊系（明示的に色分け）

#### 詳細画面のフッター
```
[戻る] [削除] ......................... [リセット] [保存]
```
- 左端: 離脱（[戻る]）
- 左寄り: 破壊的アクション（[削除]）
- 右端: 主要アクション（[保存]）

### 3.3 アイコン付与
- 動詞 + 名詞 の意味を強める時のみ `startIcon` を使う（例: `<Add />` + 「新規追加」）
- アイコンのみのボタン（`IconButton`）には必ず `Tooltip` を付ける

### 3.4 disabled 条件
- 入力不足時の disabled は OK だが、**何が足りないか** を helperText で明示
- ボタン disabled だけで終わらせず、エラー状態を視覚化する

### 3.5 ローディング中
- 保存中は `LoadingButton` 相当（spinner）+ disabled。最低 200ms 表示で「ちらつき」を防ぐ

## 4. ダイアログ

### 4.1 種類の選択

| 用途 | コンポーネント | 例 |
| --- | --- | --- |
| 編集・確認・選択 | `Dialog` (MUI) | 入院手続き、削除確認 |
| 詳細表示・閲覧 | `Dialog fullWidth maxWidth="md"` | 看護記録（参照モード） |
| 一覧サブビュー（多項目）| `Drawer anchor="right"` | 未割当患者一覧 |
| 軽通知 | `Snackbar` | 保存完了 |

### 4.2 ヘッダー
- `DialogTitle` に主タイトル + 必要に応じてサブタイトル（caption + text.secondary）
- `× ボタン` は **右上に置かない**（保存/キャンセルの導線を明確にするため）。代わりに ESC / 背景クリック / フッター [キャンセル] で閉じる

### 4.3 フッター（DialogActions）
- 上記 「ボタン § 3.2」 に従う
- 確認系ダイアログ（破壊的アクション）は**主要ボタンを最初は disabled** にし、何らかの確定操作（理由入力等）で有効化

### 4.4 閉じる挙動の整理

| 操作 | 期待挙動 |
| --- | --- |
| Esc | キャンセル相当（変更破棄） |
| 背景クリック | キャンセル相当（変更破棄）。重要な編集中は disabled に |
| × ボタン（採用しない方針） | — |
| [キャンセル] | 変更破棄して閉じる |
| [保存] / [Primary] | 変更を確定して閉じる |

### 4.5 ネストダイアログ
- 1 ダイアログから別ダイアログを開く（例: オーダー確認 → 代行入力認証）は OK
- 2 階層まで。3 階層以上は画面遷移を検討

## 5. フォーム

### 5.1 基本パターン

```
ラベル（必須は赤 * マーク or required）
[入力フィールド                      ]
ヘルプテキスト / エラーメッセージ
```

- ラベルは MUI `TextField label` を使用（フィールド内浮き上がり）
- 必須は `required` プロパティで赤 * 表示
- ヘルプ・エラーは `helperText` に統一

### 5.2 必須・任意の表記
- **必須**: 赤 * マーク（required prop）+ ラベル末尾に「(必須)」併記不要
- **任意**: ラベル末尾に「（任意）」を明記。required prop は付けない
- 統一: フォーム全体で「必須」「任意」両方の表記を混在させない

### 5.3 バリデーション
- 入力中は触らない（onBlur 時 or submit 時にチェック）
- エラー: `error` prop + `helperText` で具体的な指示（例「3000 文字以内」「形式不正」）
- 文字数カウント: `helperText` に `${現在}/${上限} 文字` 表示

### 5.4 グルーピング
- 関連項目は `Stack direction="row" spacing={1.5}` でまとめる（例: 病棟/病室/ベッド）
- 縦長フォームは `Stack spacing={2}` で十分な余白
- 横並び 3 つ以上は `Grid` を使用

### 5.5 読み取り専用
- 編集できないフィールドは `InputProps={{ readOnly: true }}` + 軽くグレーアウト（自動）
- ラベルは「（参照）」等の追記なし、ラベル + 値だけで「編集できないこと」を視覚的に伝える

### 5.6 未保存検知
- フォームに変更があり、保存していない状態で離脱・閉じようとした場合は確認ダイアログ
- 検知方法: `initial` snapshot との比較、または個別 dirty フラグ

## 6. テーブル

### 6.1 ヘッダー
- 背景色: `#f8fafc`（テーマ設定済）
- 太字: `fontWeight: 700`
- 並び替え可能列: `TableSortLabel`、列ヘッダ右寄せでソート方向を視覚化
- 横スクロール時のみヘッダー固定（`stickyHeader`）

### 6.2 行
- 偶数行に zebra（`#fafbfc`、テーマ設定済）
- ホバー: `bgcolor: '#f0f7ff'` + cursor: pointer（クリック可能行のみ）
- 行クリックは詳細画面遷移か選択ハイライトに使用、編集アクションは行内ボタンに置く

### 6.3 セル
- パディング: `padding: '8px 12px'`（テーマ設定済）
- フォントサイズ: `0.875rem`
- 数値・日付は右寄せ、テキストは左寄せ

### 6.4 空状態
- 「該当なし」「該当する○○はありません」等の文言を `Typography color="text.secondary"` で表示
- 大きな空状態は中央寄せ + アイコン + サブテキストで「次のアクション」を促す

### 6.5 アクション列
- 編集・削除等のアクションは右端列、`IconButton` + `Tooltip`
- 行ホバー時のみ表示する「ホバーアクション」は 5 行以上のテーブルで採用検討

## 7. ステータス表示

### 7.1 Chip の色対応

| 用途 | color | 例 |
| --- | --- | --- |
| 進行中・有効 | `primary` | 入院中、active |
| 完了・成功 | `success` | 完了、解決 |
| 注意・警告 | `warning` | 観察中、外泊中 |
| エラー・危険 | `error` | 隔離中、拘束中、未確定 |
| 補助情報 | `info` | 参考、リンク |
| 終了・無効 | `default` | 退院済、closed |

### 7.2 サイズ
- 表内・密度高: `size="small"`（高さ 26px、テーマ設定済）
- 強調: 通常サイズ（高さ 32px）

### 7.3 複数ステータス
- 1 オブジェクトに複数の独立ステータスがある場合（例: ベッドの 隔離 + 拘束 + 預り金）は **アイコン群** で重畳表示（`BedFlagIcons` パターン）
- Chip 横並びは 3 個以下推奨

## 8. 日付・時刻

### 8.1 表示フォーマット

| シーン | フォーマット | 例 |
| --- | --- | --- |
| 一覧表示・通常 | `YYYY/MM/DD` | `2026/05/04` |
| 短縮（日付のみ） | `MM/DD` | `5/4`（同年内のみ） |
| 日時 | `YYYY/MM/DD HH:mm` | `2026/05/04 14:30` |
| 相対 | 「3日前」「明日」 | 直近 7 日のみ使用、それ以外は絶対日付 |
| 期限 | 絶対日付 + 残日数 | `5/15 (残3日)` / `4/30 (5日超過)` |

### 8.2 入力
- 日付: `<input type="date">` または `DatePicker`
- 日時: `<input type="datetime-local">`
- 時刻: `<input type="time">`
- 共通: `InputLabelProps={{ shrink: true }}` を必ず付与

### 8.3 タイムゾーン
- 表示・入力ともローカル（Asia/Tokyo）
- ストア内部は ISO 文字列（`YYYY-MM-DD` または `YYYY-MM-DDTHH:mm`）で保持
- API 連携時のみ ISO8601 完全形に変換

## 9. 通知

### 9.1 種類

| 種類 | コンポーネント | 表示時間 | 用途 |
| --- | --- | --- | --- |
| 一時通知 | `Snackbar` | 4-6 秒 | 保存完了、軽い情報 |
| 永続通知 | `Alert` | ユーザーが閉じるまで | エラー、警告 |
| インライン | `Alert` (sx contained) | 永続 | フォーム内の補足説明 |

### 9.2 重要度の使い分け（severity）

| severity | 用途 |
| --- | --- |
| `success` | 完了系（「保存しました」） |
| `info` | 情報・進行（「N 件取り込みました」） |
| `warning` | 確認を促す（「未来日時のため確定できません」） |
| `error` | 失敗・致命的（「保存に失敗しました」） |

### 9.3 通知文言の書き方
- 主語を省略しすぎない: 「保存しました」より「入退院指示を保存しました」
- 結果を明示: 「N 件処理しました」「次は ○○」
- アクション可能なら ActionButton を Snackbar に置く（例: 「元に戻す」）

## 10. 破壊的操作

### 10.1 表示

| シーン | 推奨パターン |
| --- | --- |
| 一覧の行アクション | `IconButton color="error"` + Tooltip（[削除]） |
| 詳細画面 | `Button color="error"` を左下 / 編集系から離して配置 |
| ダイアログ内 | フッター左寄せ。primary（保存）から離して目立たせる |

### 10.2 確認ダイアログ
- 必ず `Dialog` で確認、`window.confirm` は使わない
- ダイアログ内容:
  - タイトル「○○を削除しますか？」（疑問形）
  - 本文: 影響範囲 + 取消し可否 + 削除対象の特定情報
  - フッター: [キャンセル] ........... [削除する (color=error variant=contained)]
- 削除 disabled 解除は **理由入力** や **typing confirmation**（「DELETE」入力）で守る

### 10.3 取消し可能性の表示
- 取消可能な場合: 「削除後 7 日間は復元可能です」等
- 取消不能な場合: 警告色のアラートで明示「この操作は取り消せません」

## 11. 未保存検知

### 11.1 検知方法
- フォームの `initial` snapshot と現在値を比較
- 大きなフォームは個別 dirty フラグ（`useFormDirty(formRef)` 等）

### 11.2 離脱時の挙動
- ブラウザ back / 別画面遷移: `useBlocker`（React Router v6.4+）で確認
- ダイアログ閉じる: 内部で確認
- ESC / 背景クリック: 重要な編集中は disabled

### 11.3 確認ダイアログ
```
タイトル: 「未保存の変更があります」
本文:    「変更を保存せずに離れますか？」
ボタン:  [キャンセル] [保存せず離れる] [保存して離れる]
```

## 12. アクセシビリティ・キーボード

### 12.1 キーボード操作

| キー | 期待挙動 |
| --- | --- |
| Tab | 次のフォーカス可能要素 |
| Shift+Tab | 前 |
| Enter | フォーム内: submit / フォーカス送り（複数行除く） |
| Esc | ダイアログ・ドロップダウン閉じる |
| Space | チェックボックス・スイッチ切替 |

### 12.2 ラベル付与
- すべての操作要素に `aria-label` または視認可能ラベル
- アイコンのみのボタンは `Tooltip` + 内部 aria-label（MUI が自動付与）

### 12.3 フォーカス管理
- ダイアログ open 時は最初の入力可能要素にフォーカス
- ダイアログ close 時は元のトリガーボタンにフォーカスを戻す（MUI default）

### 12.4 コントラスト
- 文字 / 背景比 4.5:1 以上（WCAG AA）
- リンク / アイコンは 3:1 以上

## 13. レスポンシブ

### 13.1 ブレイクポイント（MUI default）

| Key | px | 用途 |
| --- | --- | --- |
| xs | 0–600 | スマホ（運用想定外、最低限崩れない） |
| sm | 600–900 | タブレット縦 |
| md | 900–1200 | タブレット横・小型ノート |
| lg | 1200–1536 | ノート / デスクトップ |
| xl | 1536+ | 大画面 |

### 13.2 業務想定
- 主要解像度: **1366×768 〜 1920×1080**（医療現場のノート PC / デスクトップ）
- xs / sm でも崩れない実装が望ましいが優先度低

## 14. パフォーマンス

### 14.1 大量リスト
- 100 行を超える場合は仮想スクロール (`react-window`) 検討
- ページング（10 / 25 / 50 / 100）を併用

### 14.2 重い計算
- `useMemo` で派生値キャッシュ
- 並び替え・絞り込みは `useMemo`、入力遅延は `useDeferredValue` / debounce

### 14.3 画像・ファイル
- アップロードはプログレス表示
- 画像はプレースホルダー → 遅延読み込み

## 15. 用語・表記

[docs/specs/_terminology.md](specs/_terminology.md) に集約。新規用語が出たら必ず追記する。

主要表記ルール（抜粋）：
- 「お客様」ではなく **「患者」**
- 「ユーザー」ではなく **「医師」「看護師」「事務」** 等の役割名
- 句読点: 全角「、」「。」 + 半角の区別なし、行末「。」省略可（タイトル除く）
- 数値: 桁区切りカンマ（123,456）
- 単位: 数値と単位の間に半角スペースなし（`5kg` `30分`）
