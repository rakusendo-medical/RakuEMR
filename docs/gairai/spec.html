3. 認証仕様

認証フロー

sequenceDiagram participant U as ユーザー participant C as Client (React) participant S as Server (API) U->>C: ログイン画面アクセス U->>C: ID/パスワード入力 C->>S: POST /auth/signin S-->>C: 認証トークン C->>C: Redux authSlice にトークン保存 C->>C: Redux userSlice にユーザー情報保存 C->>C: localStorage に永続化 (redux-persist) C->>U: 患者検索画面へリダイレクト

認証保護レイヤー

コンポーネントチェック内容失敗時の動作
AuthInitializerアプリ起動時にトークン有効性を確認ログイン画面へリダイレクト
ProtectedRoute認証状態（トークン有無）のチェック/signin へリダイレクト
ProtectedRouteNoPatientIdpatientIdパラメータが数値であることを検証/patientSearch へリダイレクト

APIリクエスト認証

fetchBaseQueryWithAuth が全APIリクエストにAuthorizationヘッダーを自動付与します。トークン失効時は自動的にログアウト処理を行います。

6. API連携仕様

基盤設定

// src/common/api/fetchBaseQueryWithAuth.ts
const baseQuery = fetchBaseQuery({
  baseUrl: import.meta.env.VITE_API_URL,
  prepareHeaders: (headers) => {
    // 認証トークンを自動付与
    const token = getToken();
    if (token) headers.set('Authorization', `Bearer ${token}`);
    return headers;
  },
});

API命名規則

プレフィックスHTTP Method用途
fetch* / get*GETデータ取得
create*POST新規作成
update*PUT / PATCH更新
delete*DELETE削除

RTK Queryフック命名

// Query（GET）: useXxxQuery() / useLazyXxxQuery()
const { data } = useFetchPatientsQuery({ checkInDate });
const [trigger] = useLazyFetchAttachmentDownloadUrlQuery();

// Mutation（POST/PUT/PATCH/DELETE）: useXxxMutation()
const [createPatient] = useCreatePatientMutation();
const [updateDiagnosis] = useUpdateDiagnosisMutation();

9. キャンバス描画仕様

Fabric.js 6.6 を使用したキャンバス描画機能を提供します。

使用箇所

機能画面用途
家系図描画カルテ記載患者の家系図を描画
シェーマ描画カルテ記載 / 処置オーダー身体部位のシェーマを描画

実装

  • 描画データはJSON形式でシリアライズして保存
  • 読み取り専用表示は CanvasRenderer コンポーネントを使用
  • 編集時は SchemaDrawer コンポーネントを使用
  • カスタムフック useDrawForm() で描画状態を管理
