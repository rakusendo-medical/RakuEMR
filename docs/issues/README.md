# Issue ドラフト（入院機能）

`docs/入院機能一覧.xlsx` をもとに、入院機能のユーザーストーリーとエピックを書き起こしたものです。
将来的に別リポジトリへ `gh issue create --body-file` で投入する想定で作成しています。

## ディレクトリ構成

```
docs/issues/
├── README.md          # 本ファイル
├── manifest.tsv       # 一括投入用メタデータ（タイトル・ラベル・親子関係）
├── epics/             # エピック（機能単位）
│   └── ep-XX-*.md
└── user-story/        # ユーザーストーリー（操作単位）
    └── us-XX-*.md
```

## 粒度

| 階層 | 対応列 | 数 | 例 |
| --- | --- | --- | --- |
| Epic | `機能` | 13 | `[病床管理] 病棟マップ` |
| Story | `操作内容` | 30 | `[病床管理] 病床表示` |

`業務` 列は Issue タイトルの prefix とラベル（`area/*`）として運用します。

## ロール想定

ストーリーで使用する `As a` の標準ロールは以下のとおりです。
精神科病棟も含む入院機能を想定しています（隔離拘束指示があるため）。

| 業務領域 | 主なロール |
| --- | --- |
| 病床管理（病棟運用） | 病棟事務、病棟看護師長 |
| 病床管理（指示系） | 主治医 |
| 隔離拘束 | 主治医、病棟看護師、看護師長 |
| 共通（一覧参照） | 病棟看護師 |
| 看護（実施・記録） | 病棟看護師 |
| 看護（計画・評価） | 受け持ち看護師 |

## ラベル運用

| カテゴリ | ラベル例 |
| --- | --- |
| 種別 | `epic`, `story` |
| 業務領域 | `area/bed-management`, `area/restraint`, `area/common`, `area/nursing` |
| 機能 | `feature/<機能>`（必要に応じて） |

## エピック（親子関係）

GitHub のサブイシュー機能で `epic` を親、`story` を子として紐付けます。
`manifest.tsv` の `parent_key` 列にエピックの `file` 値を入れて関係を表現しています。

投入時は2パスで処理する想定です。

1. **1パス目**: 全 Issue を `gh issue create --body-file` で作成し、Issue 番号を記録
2. **2パス目**: `parent_key` を解決し、`gh api -X POST /repos/{owner}/{repo}/issues/{n}/sub_issues` で親子付け

## 受け入れ基準（AC）の書き方

ユーザーストーリーには Given/When/Then 形式の受け入れ基準を 1〜3 件記載しています。
網羅的なテストケースではなく、ストーリーが「完了した」と判断できる主要シナリオを書いています。
詳細仕様は実装着手時にエピック単位で別途整理する想定です。

## 固有名詞ポリシー

固有名詞ポリシーはリポジトリルートの [`CLAUDE.md`](../../CLAUDE.md) に集約しています。
参照元は一律「参考システム」表記、機能名は `入院機能一覧.xlsx` ベースの自社命名に統一します。
