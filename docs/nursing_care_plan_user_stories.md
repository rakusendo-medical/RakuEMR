# 看護計画モジュール ユーザーストーリー一覧

本ドキュメントは、精神科病院向け電子カルテ(EMR)の「看護計画」モジュール設計のための、プロダクトオーナー側仕様整理である。Claude Code 等の実装支援AIに投入するプロンプト素材として利用することを想定する。

---

## 0. 前提(Context)

- 対象:精神科病院の電子カルテ看護計画モジュール。
- 利用ユーザー:看護師のみ(医師の代行記載は本フェーズでは非対象)。
- 開発スタック:React / TypeScript / MUI / Zustand(既存EMRフロントエンドに統合)。
- 本フェーズで扱う主要機能は「立案・編集・月次評価・長期目標見直し・履歴・タスク一覧」である。
- 将来拡張:医師記載、師長承認フロー、病棟別ダッシュボード、処方連携は別フェーズ。

---

## 1. 用語定義(Domain Vocabulary)

| 用語 | 定義 |
|---|---|
| 看護計画(Care Plan) | 患者に紐づく計画の総体。1患者1現行計画が原則。 |
| 長期目標(Long-term Goal) | 看護目標・退院目標を包含する1件のテキスト。患者ごとに1つ。 |
| 明細(Problem Item) | 長期目標配下にぶら下がる最小単位。領域分類・優先度・問題点・目標・OTE具体策・立案日・評価履歴を持つ。評価の単位でもある。 |
| 問題点(Nursing Diagnosis) | NANDA-I 由来のマスタから選択。明細内の1属性。 |
| 目標(短期目標) | 明細ごとの解決後の姿(状態記述)。期限は持たず、長期目標側で管理。 |
| 具体策(OTE) | Observation(観察)/ Therapy(援助)/ Education(指導)の3区分。各区分ごとに複数行のフリーテキスト。 |
| 定期評価 | 月1回、明細単位で実施。達成度・所見・次回方針を記録。 |
| 受け持ちNs | 患者担当の主責看護師。立案・評価の主体。 |
| 代行記載 | 受け持ち以外のNsが記載すること。履歴に記載者が残る。 |

---

## 2. ロール(Role)

- **受け持ちNs**:原則として立案・評価の主体。
- **看護師(全員)**:代行記載可能。読み書きともに権限上同等だが、受け持ちの情報は画面上で識別表示する。

---

## 3. ステータス遷移(Lifecycle)

### 3.1 明細(Problem Item)のライフサイクル

```
[下書き] ──(立案確定)──▶ [有効] ──(月次評価開始)──▶ [評価中]
                             ▲                           │
                             └──(継続/修正で再有効化)───┤
                                                         ▼
                                                   [クローズ]
                                                   (解決/中止/変更)
```

### 3.2 計画全体(Care Plan)のライフサイクル

```
[下書き] ──▶ [有効] ──(長期目標見直し)──▶ [クローズ(履歴)]
                 │                             ▲
                 └─(新計画作成・旧計画参照コピー)┘
```

### 3.3 UX 言語化

- **下書き**:立案途中。一覧では「未立案/作成中」として表示。
- **有効**:現行計画として画面トップに表示。患者カルテ開口時の既定ビュー。
- **評価中**:月次評価期限の7日前から「評価中」表示に切替(視覚的に注意喚起)。
- **クローズ**:履歴ビューから参照可能。編集不可。再利用は「引用コピー」経由で行う。

## 4. エピック & ユーザーストーリー

### E1. 計画立案(Planning)

- **US-1.1** 受け持ちNsとして、担当患者の看護計画を新規作成できる。初期状態は下書き。
- **US-1.2** 受け持ちNsとして、長期目標を1つ入力して保存できる。
- **US-1.3** 受け持ちNsとして、長期目標配下に明細を複数追加でき、各明細に領域分類・優先度・問題点(NANDA)・目標・OTE具体策を入力できる。
- **US-1.4** 受け持ちNsとして、NANDA-Iマスタから問題点を検索して選択できる(キーワード検索+領域絞り込み+よく使うものをサジェスト)。
- **US-1.5** 受け持ちNsとして、OTE具体策をO/T/E区分ごとに複数行のフリーテキストで入力できる。区分の並び順固定、区分内の行は並べ替え可能。
- **US-1.6** 受け持ちNsとして、下書きを「立案確定」できる。立案日は確定日で自動セットされる。
- **US-1.7** 受け持ちNsとして、計画立案を途中保存(下書き)して後で再開できる。
- **US-1.8** 看護師として、代行で立案・編集を行った場合、履歴に代行者名が残る。

### E2. 計画閲覧(View)

- **US-2.1** 看護師として、患者の現行看護計画ツリー(長期目標 → 明細一覧)を一望できる。
- **US-2.2** 看護師として、各明細の現在ステータス・最終評価日・次回評価期限を確認できる。
- **US-2.3** 看護師として、過去にクローズされた明細・計画の履歴を時系列で閲覧できる。
- **US-2.4** 看護師として、現在の看護計画を印刷・PDF出力できる。

### E3. 明細(問題点)編集・追加

- **US-3.1** 看護師として、既存明細の内容(目標・OTE)を編集できる。編集履歴が残る(誰が・いつ・何を)。
- **US-3.2** 看護師として、既存の有効計画に新しい明細を追加できる(長期目標は変更せず)。
- **US-3.3** 看護師として、明細を「解決」「中止」「変更」のいずれかの理由でクローズできる。クローズ理由と所見を記録する。
- **US-3.4** 看護師として、問題点が変化した場合、旧明細を「変更」でクローズし、新しい明細を追加する運用フローで対応できる。

### E4. 月次評価(Monthly Evaluation)

- **US-4.1** 看護師として、明細単位で月次評価を入力できる(達成度+所見+次回方針)。
- **US-4.2** 看護師として、評価と同じ画面で明細の目標・OTEを見直して修正できる(評価→改訂の動線を分断しない)。
- **US-4.3** 看護師として、評価完了時に明細のステータスを「継続」「修正して継続」「クローズ」のいずれかに確定できる。
- **US-4.4** 看護師として、明細ごとの評価履歴を時系列で参照できる。
- **US-4.5** 看護師として、対象患者の全明細を1画面で縦に並べて連続評価できる(評価画面は患者単位で入口、内部は明細連続入力UI)。

### E5. 長期目標の見直し・計画切り替え

- **US-5.1** 受け持ちNsとして、長期目標の見直しが必要なとき、現行計画をクローズし、新計画を作成できる。
- **US-5.2** 受け持ちNsとして、新計画作成時、旧計画の明細を引用コピーして立ち上げられる(粒度:明細単位で選択可)。
- **US-5.3** 看護師として、旧計画と新計画が時系列で連続した履歴として閲覧できる。

### E6. タスクリスト / ダッシュボード

- **US-6.1** 看護師として、「計画未立案」の担当患者一覧を見られる。
- **US-6.2** 看護師として、「今月評価が必要な患者」一覧を患者単位で見られる(評価期限の近い順)。
- **US-6.3** 看護師として、「評価期限超過」の患者が視覚的にアラート表示される。
- **US-6.4** 看護師として、「評価未完了(評価中のまま)」の患者一覧を見られる。
- **US-6.5**(将来拡張)師長として、病棟全体の立案・評価状況を俯瞰できる。

### E7. テンプレート・引用コピー

- **US-7.1** 受け持ちNsとして、他患者の計画から明細をコピーして自患者に追加できる。
- **US-7.2** 受け持ちNsとして、同一患者の過去計画から明細をコピーできる。
- **US-7.3** 看護師として、精神科向け標準テンプレートから明細をコピーして立ち上げられる。
- **US-7.4** 看護師として、自院で作成した良質な計画を「院内テンプレート」として登録・共有できる。
- **US-7.5** 看護師として、コピー時、立案日はコピー実行日に自動セットされる。
- **US-7.6** 看護師として、コピー時、患者固有の記述を含みうる項目(目標の具体文言・OTE本文など)に編集推奨アラートが表示される。
- **US-7.7** 看護師として、コピー元を履歴に残せる(どのテンプレ/患者から引用したか)。

### E8. 他機能連携

- **US-8.1** 看護師として、経過記録(看護記録)を書くとき、関連する明細(問題点)を選んで紐付けられる。
- **US-8.2** 看護師として、OTEの O 項目(観察項目)をフローシートの観察項目と連動させて登録できる。
- **US-8.3** 看護師として、明細に医師の指示簿項目を関連付けて参照できる。
- **US-8.4**(検討)処方連携については要件・実現性を別途評価。

### E9. 履歴・監査

- **US-9.1** 看護師として、計画・明細・評価のすべての変更履歴(誰が・いつ・何を)を参照できる。
- **US-9.2** 看護師として、代行記載の場合、代行者と受け持ちNsが区別して記録される。

### E10. 印刷・出力

- **US-10.1** 看護師として、現在の看護計画全体を所定フォーマットで印刷できる。
- **US-10.2** 看護師として、評価履歴付きで印刷できる(監査・カンファ用途)。

## 6. 今後の詰めポイント(Open Questions)

- OTE具体策における「よく使う文言」辞書・オートコンプリートの要否。
- 月次評価期限の起算日(立案日起算? 前回評価日起算? 月末固定?)。
- 引用コピー時の編集推奨アラートは、どの項目に・どの条件でフラグを立てるか。
- フローシート観察項目との連動の双方向性(O項目追加 → フローシート自動反映?)。
- 指示簿連携の UI 配置(明細側に指示簿リンク?指示簿側に明細リンク?)。
- 将来拡張(医師記載・承認フロー)を見越したデータモデルの拡張余地。
